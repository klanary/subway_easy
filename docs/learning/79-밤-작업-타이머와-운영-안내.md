# 79. 밤 작업 타이머와 변경 운영 안내

- 무엇을 만들었나: VM에서 밤 작업을 돌리는 `server/ml/deploy/subway-ml-nightly.service`·`.timer`(매일 02:40), 그것을 설치하도록 고친 `setup_vm.sh`, 운영 안내 `docs/ml/timetable-changes.md`(신호와 기준값, 의심·확정 규칙, 기록 읽는 법, 손으로 확정·되돌리기, 공식 시간표 다시 받기, 관찰 모드에서 적용 모드로 넘어가는 절차).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 시각은 02:40이다. 수집이 쉬는 01:00~05:00 안이고, 02:10 백업 뒤다. 서비스에 `After=subway-collector-backup.service`를 걸어 둘이 겹쳐도 백업이 먼저 끝나게 했다.
  - `Type=oneshot`, `Nice=10`, `MemoryMax=500M`. 메모리가 836MB인 VM에서 밤 작업이 수집기를 밀어내지 않게 하려는 것이다. 한도를 넘으면 밤 작업만 죽고 다음 밤에 따라잡는다.
  - 서비스 파일에는 `--enforce`를 넣지 않았다. 기준값이 검증되기 전에는 기록만 해야 한다. 테스트가 "서비스 파일에 `--enforce`가 없다"를 본다.
  - `Persistent=true`라서 02:40에 VM이 꺼져 있었으면 켜진 뒤에 돈다.
- 막혔던 점과 해결:
  - `systemd`는 Windows에서 돌려 볼 수 없어, 단위 파일의 내용과 스크립트 문법만 테스트로 고정했다. **VM에는 아직 반영하지 않았다**(사용자에게 묻고 한다).
  - 공식 시간표 다시 받기는 일반 인증키가 필요한데 VM에는 그 키가 없다. 문서에 "지금은 개발 PC에서만 돌릴 수 있고, 어디서 돌릴지는 정하지 않았다"고 적었다.
- 예상 면접 질문과 내 답:
  - Q. 주기 작업 둘이 순서를 지켜야 할 때 어떻게 하나?
  - A. 시각을 떼어 놓는 것만으로는 부족하다. 앞 작업이 오래 걸리면 겹친다. `systemd`의 `After=`로 순서를 걸고, 뒤 작업이 "앞 작업이 안 끝났어도 틀리지 않게"(여기서는 수집 DB를 읽기 전용으로 열고, 이미 처리한 날은 건너뛰게) 만든다.
