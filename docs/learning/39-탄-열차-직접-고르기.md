# 39. 탄 열차 직접 고르기와 "다른 열차였어요"

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 탑승 중 세션 화면에 추적 상태 줄("하남검단산행 열차 실시간 추적 중", "실시간 추적 끊김" 등)과 [탄 열차 고르기]·[열차 바꾸기]를 두고, 누르면 탈 역 근처 열차 목록("OO행 · 지금 XX역")을 보여 준다. 위치로 탑승을 알아낸 알림에는 [다른 열차였어요] 버튼을 달아 바로 이 목록으로 오게 했다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 목록은 지금 추적 중인 단계의 탈 역과 그 단계의 다음 정거장(방향)으로 서버에 묻는다. 방향 판단은 노선 표가 있는 서버가 하므로 앱은 정거장 이름만 보낸다(위치 결합 스펙 6.3).
  - 고른 열차는 상태 머신의 `TrainIdentified(…, MANUAL)` 사건으로 보낸다. 직접 고르기는 화면에서 하므로, 권한 문제로 서비스가 꺼져 있었으면 이때 다시 켤 수 있다.
  - 알림에서 열 때는 화면 이동 인자(`SessionDest(pickTrain = true)`)로 목록을 연다. 화면을 돌려도 다시 열리지 않게 한 번 연 것을 `rememberSaveable`로 기억한다.
  - 목록을 못 불러오면 다른 화면과 같은 기준의 문구(오프라인, 연결 실패, 서버 문구)를 보여 준다.
- 막혔던 점과 해결:
  - `SessionDest`를 인자가 있는 data class로 바꾸자, 예전처럼 `navigate(SessionDest)`로 부르던 곳이 컴파일은 되지만 실행 중에 "Companion 직렬화기 없음" 오류로 죽었다(`navigate`가 `Any`를 받기 때문). 모든 호출을 `SessionDest()`로 바꾸고 내비게이션 테스트가 인자 왕복을 확인하게 했다.
- 예상 면접 질문과 내 답:
  - Q. 자동 감지가 다른 열차를 고르면? A. 알림의 [다른 열차였어요]나 세션 화면의 [열차 바꾸기]로 언제든 바꿀 수 있고, 바꾸면 그 열차 기준으로 다시 추적한다.
  - Q. 타입 안전 내비게이션에서 object를 data class로 바꿀 때 조심할 점은? A. 객체 이름만 넘기는 호출이 컴파일되지만 실행 중에 실패하므로, 호출하는 곳을 모두 찾아 바꾸고 테스트로 확인해야 한다.
