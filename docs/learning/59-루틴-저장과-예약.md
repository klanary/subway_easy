# 59. 루틴 저장과 다음 실행 예약

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: Room `routines` 표(이름, 출발·경유·도착 역, 고른 경로 JSON, 요일 비트, 시각, 걷는 시간, 진동 알림, 켜짐)와 저장소. 저장·켜기·끄기·삭제 때마다 다음 실행 시각 하나를 `setAlarmClock`으로 건다(요청 코드 5000 + 루틴 id).
- 왜 이렇게 했나:
  - 반복 알람(`setRepeating`)은 정확하지 않다. 다음 한 번만 정확하게 걸고, 울리면 그다음을 다시 건다(A10).
  - 다음 실행 시각 계산(`nextOccurrence`)을 순수 함수로 떼어 요일·자정 넘김·같은 분 같은 경계를 테스트한다.
  - 요일은 비트(월 = 1 … 일 = 64) 하나의 정수로 저장한다. 표 하나에 열 하나로 끝난다.
  - 정확한 알람 권한이 없으면 `setAndAllowWhileIdle`로 대신한다(조금 늦을 수 있음).
- 막혔던 점과 해결:
  - DB 버전이 2에서 3으로 바뀐다. 배포 전이라 파괴적 마이그레이션 설정을 그대로 둔다.
- 예상 면접 질문과 내 답:
  - Q. 요일을 하나도 안 고르면? A. 다음 실행 시각이 없어 예약하지 않는다(알람 취소).
