# 62. 수집기 키 고리

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: `server/ml/keys.py`. 수집기가 쓸 수 있는 키 이름 세 개(`position`, `spare1`, `spare2`)와 환경 변수 이름을 코드에 고정했다(`KEY_ENV`). `load_keys`는 `.env`와 환경 변수에서 이 세 개만 읽고, `KeyRing`은 지금 쓸 키를 순서대로 고르며 한도에 걸린 키를 그날(KST) 쉬게 한다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 수집기가 서버의 실시간 키를 쓰면 앱이 멈춘다(설계 §7). 그래서 "쓰지 말 것"을 규칙으로 두지 않고, **읽는 코드 자체가 없게** 했다. 서버의 `Settings`를 재사용하면 실시간 키도 메모리에 올라오므로 쓰지 않았다.
  - 대안: 키 이름을 CLI 옵션으로 받기. 실수로 다른 키 이름을 넣을 수 있어서 버렸다. `KeyRing`은 목록에 없는 이름이 오면 `ValueError`를 낸다.
  - 정지는 "이름 → 막힌 날짜"만 기억한다. 날짜가 바뀌면 자동으로 풀리므로 자정에 따로 초기화할 필요가 없다.
- 막혔던 점과 해결:
  - `.env`의 순서와 상관없이 위치 → 예비 1 → 예비 2 순서를 지켜야 한다. `KEY_ENV`(dict)의 순서를 기준으로 다시 만든다.
  - 지금 `.env`에는 예비 키가 없다. 값이 빈 키는 고리에서 빠지므로 위치 키 하나로도 돈다.
- 예상 면접 질문과 내 답:
  - Q. 키가 로그에 남지 않게 하려면 무엇이 가장 확실한가?
  - A. 값을 다루는 코드를 한 곳으로 모으고, 나머지는 이름만 다루게 한다. 여기서는 키 값이 `KeyRing.current`의 반환값으로만 나가고, DB·로그에는 이름만 쓴다. 그리고 "DB 파일 바이트에 키 문자열이 없다"를 테스트로 확인한다.
