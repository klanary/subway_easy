# 72. 역 별칭 추가와 VM 설치 스크립트

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나:
  - 열차 위치 API가 쓰는 이름 다섯 개를 역 표에 이었다. `server/scripts/build_stations.py`에 `EXTRA_ALIASES`(성수종착 → 성수, 세종왕릉 → 세종대왕릉, 한국항공대 → 화전, 시우 → 원곡, 4.19 민주묘지 → 4.19민주묘지)를 두고 `stations.sqlite`를 다시 만들었다.
  - VM에 수집기를 한 번에 설치하는 `server/ml/deploy/setup_vm.sh`와 `systemd` 단위 파일 세 개(수집기 서비스, 백업 서비스, 백업 타이머). `docs/ml/collector.md`에 "빠른 설치"를 더했다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 별칭을 DB에 직접 `INSERT`하지 않고 빌드 스크립트의 표에 적었다. `stations.sqlite`는 원본에서 다시 만드는 결과물이라, 직접 고치면 다음 빌드 때 사라진다.
  - 다시 만들기 전에 임시 파일로 빌드해 지금 DB와 표마다 견줬다. 달라진 것은 별칭 5개와, 새 이름으로만 역 코드가 오던 두 역(원곡·화전)의 시간표 역 코드 2개뿐이었다. 의도한 변화만 있는 것을 확인하고 바꿨다.
  - 손으로 적은 별칭은 가리키는 역이 있을 때만 넣는다. 테스트용 표본 데이터에는 그 역이 없기 때문이다.
  - 설치 스크립트는 키 값을 다루지 않는다. `.env`에 이름 세 줄의 빈 틀만 만들고, "값이 있는 줄이 있는가"만 보고 시작 여부를 정한다. 키가 없으면 멈추고, 넣은 뒤 같은 스크립트를 다시 돌리면 이어서 진행한다(여러 번 돌려도 되는 구조).
  - 단위 파일의 경로·계정은 `@SERVER_DIR@`·`@USER@`로 비워 두고 스크립트가 채운다. 계정 이름이나 저장소 위치가 달라도 파일을 고칠 필요가 없다.
- 막혔던 점과 해결:
  - 한국항공대와 시우는 표에 아예 없는 줄 알았는데, 역 이름이 바뀐 것이었다(옛 화전, 옛 원곡). 역사마스터는 옛 이름, 위치 API와 역 정보 API는 새 이름을 쓴다.
  - 이 저장소는 Windows에서 `core.autocrlf=true`라 셸 스크립트가 CRLF로 풀릴 수 있다. CRLF면 리눅스에서 실행되지 않으므로 `.gitattributes`에 `server/ml/deploy/* text eol=lf`를 넣고, 테스트가 `\r`이 없는지 본다.
  - `systemd`는 Windows에서 돌려 볼 수 없다. 대신 단위 파일에 `Restart=always`, 실행 명령, 02:10 타이머가 있는지와 스크립트가 올바른 bash인지(`bash -n`)를 테스트로 고정했다. **VM에서 실제로 돌려 본 것은 아니다.**
- 예상 면접 질문과 내 답:
  - Q. 설치 스크립트를 여러 번 돌려도 안전하게 만들려면?
  - A. 각 단계를 "이미 되어 있으면 건너뛴다"로 쓴다. 가상 환경은 없을 때만 만들고, `.env`는 없는 줄만 더하고, 단위 파일은 매번 같은 내용으로 덮어쓴다. 그러면 중간에 실패해도 처음부터 다시 돌리면 된다.
