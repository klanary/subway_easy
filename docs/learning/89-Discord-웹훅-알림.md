# 89. Discord 웹훅 알림

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: `server/ml/alerts.py`에 Discord 웹훅으로 글을 보내는 함수를 만들고, 밤 작업(`ml.nightly`)과 공식 시간표 받기(`ml.b0`)의 `main`에 붙였다. 변경이 확정되면 그 내용을, 작업이 실패하면(종료 코드 1·2, 예기치 않은 예외) 실패 알림을 보낸다. 웹훅 URL은 `.env`의 `DISCORD_WEBHOOK_URL`에서 읽고, 없으면 아무것도 보내지 않는다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 알림 실패는 작업 실패가 아니다. 보내기가 실패해도 예외를 올리지 않고, 작업의 종료 코드를 그대로 돌려준다. 알림 때문에 밤 작업이 실패로 보이면 원인을 헷갈린다.
  - 실패 알림은 `main`에서 한 번만 보낸다. `run_nightly` 안의 여러 실패 지점마다 보내면 하룻밤에 알림이 여러 개 온다. 종료 코드 하나로 모아 보내고, 자세한 내용은 `journalctl` 명령을 알려 준다.
  - 계획(Task 10)에는 Telegram도 있었지만 사용자가 Discord로 정해 Discord만 만들었다.
- 막혔던 점과 해결:
  - 웹훅 URL 안에 비밀 토큰이 들어 있다. 우리 로그에는 예외 종류 이름만 남기지만, httpx 자체가 INFO로 "HTTP Request: POST <URL 전체>"를 찍는다. 밤 작업은 INFO로 돌므로 그대로면 `journalctl`에 토큰이 남는다. respx로 흉내 낸 요청에서는 이 로그가 나오지 않아 테스트가 이를 잡지 못했다. 그래서 "httpx·httpcore 로거가 WARNING 이상인지"를 직접 확인하는 테스트로 바꿨다.
  - 본문은 `json=` 대신 직접 `json.dumps(ensure_ascii=False)`로 만들었다. httpx 버전에 따라 `json=`의 인코딩 방식(한글 이스케이프, 공백)이 달라 테스트가 흔들린다.
- 예상 면접 질문과 내 답:
  - Q. 알림이 꼭 가야 하는 상황(디스크 가득 등)에서 알림 자체도 실패하면?
  - A. 지금은 놓친다. 그래서 알림은 보조 수단이고, 진짜 기록은 `journalctl`과 `changes.md`다. 더 확실히 하려면 바깥에서 "오늘 결과물이 갱신됐나"를 보는 감시(예: 서버가 결과물 날짜를 확인)가 필요하다.
