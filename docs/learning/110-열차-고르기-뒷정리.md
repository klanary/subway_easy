# 110. 열차 고르기 뒷정리: 취소, 떠난 열차, 시각 표기, 이분 탐색

- 무엇을 만들었나: 최종 리뷰에서 미뤄 둔 작은 문제를 정리했다.
  - "더 늦은 열차 불러오기" 작업을 기억해 두었다가 다른 경로를 고르거나 다시 검색하면 취소한다. 늦게 온 응답이 새 결과에 섞이지 않는다.
  - 놓침 알림 본문을 "이미 타셨다면 무시하세요. 아니면 경로에서 다른 열차를 골라 다시 시작해 주세요"로 바꿨다. 탔는데 [탑승했어요]를 안 누른 사람을 위한 것이다.
  - 이미 떠난 후보 열차는 흐리게 보이고 "이미 떠남"을 붙인다.
  - 시각 표기를 문자열 자르기(`substring(11, 16)`)에서 `OffsetDateTime` 파싱으로 바꿨다. 초나 소수점이 있어도 맞게 나온다.
  - `picks`·`pickedRoute`를 상태마다 한 번만 계산한다(`by lazy`).
  - 서버 후보 수집은 정차별 출발 시각 배열에서 창의 처음을 이분 탐색으로 찾고, 끝을 넘으면 멈춘다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - data class 본문의 `by lazy`는 `copy`마다 새 인스턴스라 값이 낡지 않는다. 상태에 계산값을 따로 저장하면 갱신을 놓칠 위험이 생긴다.
  - 이분 탐색은 RAPTOR가 이미 쓰는 `earliest_trip`(정차마다 출발 순 배열)을 그대로 썼다.
- 막혔던 점과 해결:
  - 취소 테스트는 테스트 디스패처가 작업을 바로 돌리지 않는 점을 이용해, 응답 전에 경로를 다시 고르는 상황을 만들었다.
- 예상 면접 질문과 내 답:
  - Q. 화면을 떠난 뒤 도착한 비동기 응답은 어떻게 다루나?
  - A. 작업 핸들을 들고 있다가 새 요청이나 선택이 오면 취소한다. 응답을 반영할 때도 지금 상태 기준으로 합친다.
