# 14. 내 장소·즐겨찾기·최근 검색 저장소와 설정 저장

- 무엇을 만들었나: Room 데이터베이스(내 장소, 즐겨찾는 역, 자주 가는 경로와 사용 기록, 최근 검색 — 스펙 7.2의 다섯 테이블)와 DAO, DataStore에 저장하는 알림 설정(`SettingsStore`, 스펙 8.6 기본값), 이를 감싼 저장소(`MyPlaceRepository`, `FavoriteRepository`, `RecentSearchRepository`).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 구조화된 목록(장소·즐겨찾기·검색 기록)은 Room, 몇 개의 설정 값은 DataStore로 나눴다. 설정 몇 개를 위해 테이블을 만들 필요가 없고, 목록은 정렬·중복 제거·개수 제한 같은 질의가 필요하다(스펙 5.3).
  - 최근 검색의 중복 제거는 `dedupeKey` 유일 색인과 `REPLACE` 삽입으로 했다. 같은 역을 다시 고르면 기존 행이 지워지고 새 시각으로 들어가 맨 위로 온다. 이어서 20개를 넘는 오래된 행을 지운다. 두 단계를 `@Transaction`으로 묶어 중간 상태가 보이지 않는다.
  - 집·학교·회사는 하나씩만 둔다. 같은 종류를 지우고 넣는 것을 한 트랜잭션으로 했다.
  - 자주 가는 경로를 지우면 사용 기록도 외래 키 CASCADE로 함께 지워진다. 고아 기록이 정렬 계산에 섞이지 않는다.
  - 테이블 다섯 개를 모두 버전 1에 넣었다. P4가 자주 가는 경로를 쓸 때 마이그레이션이 필요 없다.
- 막혔던 점과 해결:
  - Robolectric이 "Android SDK 36 requires Java 21"로 실패했다. 개발 PC와 CI는 JDK 17이라, 저장소 테스트는 SDK 35로 돌리게 `robolectric.properties`에 적었다. DAO 동작은 SDK 버전과 관계없다.
  - 그다음에는 `UnsatisfiedLinkError: no K3fAndroid`가 났다. Robolectric이 앱의 `App.onCreate`를 실행하면서 카카오 지도 SDK의 네이티브 라이브러리를 불러왔기 때문이다. 저장소 테스트에는 `App`이 필요 없어, 기본 `Application`으로 돌리게 설정했다.
- 예상 면접 질문과 내 답:
  - Q. 최근 검색이 20개를 넘지 않는 것을 어떻게 보장하나요? A. 기록할 때마다 같은 트랜잭션에서 `usedAt` 내림차순 상위 20개에 들지 않는 행을 지운다. 테스트로 25개를 넣고 20개만 남는지, 가장 최근 항목이 맨 위인지 확인했다.
  - Q. 왜 서버가 아니라 기기에 저장하나요? A. 집·학교 위치는 민감한 개인정보다. 로그인 없이 기기에만 두면 서버가 개인정보를 갖지 않는다(스펙 5.4).
