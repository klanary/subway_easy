# 91. 서버 호출 한도: 0은 "제한 없음"

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 서버의 외부 API별 하루 호출 한도(`QuotaGuard`)에서 한도 0을 "제한 없음"으로 읽게 했다. 서울시 실시간·시간표 한도의 기본값을 1,000에서 0으로 바꿨다. 카카오 길찾기는 실제 한도가 있어 1,000 그대로다. `/v1/metrics`의 `dailyLimit`은 제한이 없으면 `null`이다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 서울시 키는 2026-11-15부터 한도가 없는데, 서버는 예전 한도(1,000회)를 스스로 지키고 있었다. 이용자가 늘어 하루 1,000회를 넘으면 키는 멀쩡한데도 서버가 "한도 초과"를 냈을 것이다.
  - 한도를 아주 큰 수로 두는 방법도 있었지만, 그러면 "80%부터 캐시를 3배로 늘림" 규칙이 의미 없는 숫자에 걸리고 지표도 오해를 부른다. 0 = 없음으로 두고 그 규칙은 건너뛴다.
  - 보호를 다 끄지는 않았다. 호출 수는 계속 세고, 서울시가 한도 초과로 답하면(`mark_exhausted`) 그날은 멈춘다. 한도가 다시 생겨도 서버가 같은 요청을 계속 두드리지 않는다.
  - 환경 변수(`SEOUL_REALTIME_DAILY_LIMIT` 등)로 다시 숫자를 줄 수 있다.
- 막혔던 점과 해결:
  - 지표 응답 모델의 `daily_limit`을 `int | None`으로 바꿔야 했다. 앱은 이 값을 읽지 않는 것을 확인했다(`android/`에 `dailyLimit` 없음).
- 예상 면접 질문과 내 답:
  - Q. 한도가 없는데 왜 호출 수를 세나?
  - A. 비용과 이상 징후를 보기 위해서다. 갑자기 호출이 늘면 캐시가 깨졌거나 누군가 과하게 부르는 것이다. 또 한도가 다시 생겼을 때 얼마나 쓰고 있었는지 바로 알 수 있다.
