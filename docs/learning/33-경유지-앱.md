# 33. 경유지 1곳 추가 (앱)

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 경로 흐름 상태(`RouteFlowState`)에 경유지 칸(`via`, `viaVisible`)을 더하고, 경로 편집 화면의 "+ 경유지" 버튼·[×], 지도 핀 선택의 [경유] 버튼, 경로 상세 단계 목록의 "경유지: OO" 구분선을 붙였다. 검색할 때 경유지를 서버에 함께 보낸다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 경유지 칸은 "+ 경유지"를 누를 때만 펼친다(스펙 4.2). 칸을 숨기면 경유지 값도 지운다. 숨겨진 칸에 값이 남아 있으면 화면에 안 보이는 경유지로 검색되기 때문이다.
  - 출발↔도착 바꾸기는 경유지를 그대로 둔다. 집→학원→학교를 바꾸면 학교→학원→집이 되는 것이 자연스럽다.
  - 출발·경유·도착 중 하나라도 바뀌면 이전 검색 결과를 지운다(기존 규칙과 같음).
- 막혔던 점과 해결:
  - 서버의 경유지 합성(P4 Task 10)은 아직 없다. 서버 경로 API(P2 Task 11·12)가 먼저 있어야 해서 이번에는 앱 쪽만 만들었다. 서버가 `via`를 모르는 동안에는 경유지를 넣어도 출발→도착 경로만 온다.
- 예상 면접 질문과 내 답:
  - Q. 화면 세 개(편집·결과·상세)가 같은 경유지 값을 어떻게 공유하나? A. 내비게이션 중첩 그래프에 ViewModel 하나를 두고 세 화면이 그 인스턴스를 함께 쓴다. 검색·지도 화면은 고른 값을 `PickResult`로 돌려주고, 편집 화면이 슬롯(출발·경유·도착)에 맞게 넣는다.
