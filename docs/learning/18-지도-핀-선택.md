# 18. 지도 감싸개와 지도 핀 선택

- 무엇을 만들었나: 카카오 지도 SDK를 Compose에서 쓰는 `KakaoMapView`(생명주기 연결, 초기화 실패 시 대체 문구, 카메라 이동 종료 알림), 가운데 고정 핀으로 위치를 고르는 지도 핀 선택 화면과 `MapPickViewModel`(주소와 가장 가까운 역 카드). P1의 지도 실험 화면은 지웠다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 핀을 지도 위에 고정하고 지도를 움직이게 했다. 핀을 끌어 옮기는 방식보다 손가락에 가려지지 않고, 카메라가 멈춘 가운데 좌표 하나만 보면 된다.
  - 카메라가 멈추고 500ms 동안 다시 움직이지 않을 때만 주소를 조회한다(`debounce`, 스펙 7.3). 지도를 이리저리 끄는 동안 좌표→주소 API(하루 한도)를 낭비하지 않는다. `flatMapLatest`로 늦게 온 이전 위치의 주소가 새 위치를 덮지 않게 했다.
  - 바다처럼 주소가 없거나 근처 2km에 역이 없어도 카드는 "주소 정보 없음" 등으로 채우고, 주소 조회가 실패해도 핀 좌표로는 지정할 수 있다. 지도 초기화가 실패하면 지도 자리에만 "지도를 불러오지 못했어요"가 뜨고 화면의 나머지는 동작한다(스펙 4.5).
  - 지도 감싸개를 따로 둔 것은 경로 상세(P3 Task 9)가 같은 지도로 경로선을 그리기 때문이다.
- 막혔던 점과 해결:
  - 검색 화면에서 "지도에서 선택"을 열고 위치를 고르면, 결과가 바로 이전 화면(검색)에만 들어가 경로 편집에 반영되지 않았다. 결과를 넣을 화면을 back stack에서 찾아(검색·지도 선택 화면은 건너뜀) 그 화면까지 한 번에 돌아가게 `returnPick`을 고쳤다. 이 동작은 Robolectric으로 실제 내비게이션 back stack을 만들어 테스트한다.
  - 그 테스트는 처음에 "setViewModelStore()를 먼저 부르라"는 오류로 실패했다. back stack entry의 SavedStateHandle을 쓰려면 NavController에 생명주기와 ViewModelStore가 있어야 해서, 테스트 준비에 둘을 넣었다.
- 예상 면접 질문과 내 답:
  - Q. View 기반 SDK를 Compose에서 쓸 때 주의할 점은? A. View를 한 번만 만들고(`remember`), 화면 생명주기를 SDK의 resume·pause에 연결하고, 콜백이 오래된 람다를 붙잡지 않게 `rememberUpdatedState`로 최신 람다를 부른다.
