# 08. 외부 호출 시간 제한·재시도·한도 처리와 로그 가리기

- 무엇을 만들었나: 모든 외부 API 호출이 거치는 `call_upstream`(시도마다 5초 제한, 실패하면 0.5초 뒤 1회 재시도, 호출 한도 확인·기록, 429면 그날 호출 중단), 로그용 URL 가리기(`mask_url`), 한 줄 JSON 로그 설정(`configure_logging`), 앱 전체가 함께 쓰는 `httpx.AsyncClient`(앱 종료 때 닫음).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 재시도·한도·로그를 클라이언트마다 따로 쓰면 하나만 빠져도 한도가 새거나 키가 로그에 남는다. 한 함수로 모아 서울시·카카오 클라이언트가 모두 같은 규칙을 따르게 했다.
  - 재시도는 1회뿐이다. 앱이 기다리는 시간이 최대 약 10.5초(5초 + 0.5초 + 5초)로 제한되고, 한도가 적은 API(하루 1,000회)를 재시도로 낭비하지 않는다.
  - 429는 재시도하지 않는다. 한도가 다 찼는데 다시 부르면 호출만 늘어난다. 대신 `mark_exhausted()`로 그날 호출을 멈추고 만료 캐시로 응답한다.
  - 429가 아닌 4xx는 예외로 바꾸지 않고 응답을 돌려준다. 카카오의 "출발지·도착지가 같음" 같은 오류 코드는 경로 클라이언트만 해석할 수 있기 때문이다.
  - 서울시 API는 키가 URL 경로에 들어간다. httpx의 기본 INFO 로그가 그 URL을 그대로 남기므로 httpx 로거를 WARNING으로 올리고, 우리 로그에는 `mask_url`로 가린 URL만 쓴다. 좌표는 소수점 3자리(약 100m)로 줄여 사용자의 정확한 위치가 로그에 남지 않게 했다.
  - `httpx.AsyncClient`는 앱 전체가 하나를 함께 쓴다. 연결을 재사용해 외부 호출이 빨라진다.
- 막혔던 점과 해결:
  - 테스트 시간이 0.1초에서 4초로 늘었다. 원인은 `httpx.AsyncClient`를 만들 때마다 SSL 인증서 묶음을 읽는 시간(약 0.18초)이었다. 앱을 만드는 테스트마다 생기는 비용이라 그대로 두었다.
- 예상 면접 질문과 내 답:
  - Q. 시간 제한을 httpx 옵션이 아니라 `asyncio.timeout`으로도 건 이유는? A. httpx의 시간 제한은 연결·읽기 같은 단계별 제한이라, 느린 응답이 조금씩 계속 오면 전체 시간이 길어질 수 있다. `asyncio.timeout`은 시도 하나의 전체 시간을 5초로 묶는다.
  - Q. 로그에 키가 남지 않는 것을 어떻게 확인했나요? A. 테스트(`test_seoul_key_never_logged`)가 실제 호출 흐름을 돌린 뒤 모든 로그 기록을 문자열로 바꿔 키 문자열이 없는지 검사한다.
