# 31. 알림 권한이 없을 때 앱 안 안내

- 무엇을 만들었나: 알림 권한을 거부한 사용자를 위한 앱 안 모드. 세션 화면이 보이는 동안 1초마다 "지금 울릴 알람"(`dueAlarms`)을 확인해 세션에 넘기고, 대기 단계면 실시간 조회도 화면이 대신 돌린다. 알림 대신 대화상자와 진동 한 번으로 알린다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 알림 권한이 없으면 백그라운드에서 사용자에게 알릴 길이 없다. 그래서 세션을 저장하지 않고 알람·포그라운드 서비스도 쓰지 않으며, 화면이 열려 있는 동안에만 안내한다(스펙 8.6). 화면 위에 "알림 권한이 없어 이 화면에서만 안내해요" 띠를 둬 사용자가 한계를 알게 했다.
  - 울릴 알람 계산(`dueAlarms`)을 순수 함수로 떼어 AlarmManager가 하던 일을 그대로 흉내 냈다. 세션 상태 머신은 보통 모드와 앱 안 모드를 구별하지 않고 같은 `AlarmFired` 이벤트를 받는다.
  - 탑승 단계에서 화면을 잠시 떠났다 돌아오면 그사이 놓친 지점을 순서대로 모두 알린다. 대기 단계는 출발 알림 뒤 그 열차를 기다리는 잠금이 있으면 다시 울리지 않는다.
  - 조회는 대기 단계에 들어설 때만 시작한다. 상태 전체를 지켜보면 조회 결과로 상태가 바뀔 때마다 조회가 다시 시작돼 끝없이 서버를 부르게 된다. 그래서 "대기 단계인가"만 뽑아 바뀔 때만 반응하게 했다(`map` + `distinctUntilChanged` + `collectLatest`).
- 막혔던 점과 해결:
  - 진동은 `VIBRATE` 권한(설치할 때 자동 허용)이 필요해 매니페스트에 더했다.
  - 1초 반복과 30초 조회를 가상 시간 테스트로 확인했다(`advanceTimeBy`).
- 예상 면접 질문과 내 답:
  - Q. 권한을 거부한 사용자도 기능을 쓸 수 있게 하려면? A. 기능을 막지 않고 할 수 있는 만큼(화면이 열려 있는 동안) 동작하게 하고, 한계를 화면에 분명히 보이며, 설정에서 바꿀 길([설정 열기])을 남긴다.
  - Q. `collectLatest`와 `distinctUntilChanged`를 같이 쓴 이유는? A. 같은 값이 연달아 오면 무시하고(`distinctUntilChanged`), 값이 바뀌면 이전 작업을 취소하고 새로 시작한다(`collectLatest`). 대기 단계를 벗어나면 조회가 바로 멈춘다.
