# 16. 역·장소 통합 검색 화면

- 무엇을 만들었나: 검색창 하나로 역(이름·초성)과 장소를 함께 찾는 화면과 `SearchViewModel`. 내 장소·최근 검색을 함께 보여주고, 역 결과마다 [실시간] 버튼으로 역 상세를 연다. 고른 항목은 최근 검색에 남기고 이전 화면에 돌려준다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 입력이 멈추고 300ms 뒤에 검색한다(`debounce`). 글자마다 서버를 부르면 카카오 키워드 검색 한도와 서버 요청 제한을 금방 쓴다.
  - `flatMapLatest`로 새 검색어가 오면 이전 검색을 취소한다. 느리게 도착한 이전 검색어의 결과가 새 결과를 덮어쓰는 문제(경쟁 상태)를 구조적으로 막는다. 테스트가 "홍"의 장소 검색을 2초 늦추고 "홍대"를 입력해, 마지막 결과만 남는 것을 확인한다.
  - 역과 장소 검색을 `channelFlow` 안에서 동시에 하고, 먼저 끝난 쪽부터 화면에 보낸다. 각자 `UiState`를 가져 장소 검색이 실패해도 역 결과는 보인다.
  - 현재 위치는 처음 장소 검색 때 한 번만 구한다(`async(LAZY)`). 위치를 얻는 데 최대 5초가 걸릴 수 있어 검색마다 구하면 느려진다. 역 검색은 위치를 기다리지 않는다.
  - 검색어가 비면 서버를 부르지 않고 내 장소·최근 검색만 보여준다.
- 막혔던 점과 해결:
  - 시간 의존 동작(300ms, 2초 지연)을 실제로 기다리지 않으려고, ViewModel의 Main 디스패처를 테스트 디스패처로 바꾸는 `MainDispatcherRule`을 썼다. `runTest`가 같은 가상 시계를 써서 `advanceTimeBy`로 시간을 움직인다.
  - 개발 PC에 기기가 없어 "ㅎㄷㅇㄱ → 홍대입구" 화면 확인은 서버 배포 뒤 실기기에서 해야 한다.
- 예상 면접 질문과 내 답:
  - Q. `flatMapLatest`와 `switchMap`(RxJava)의 관계는? A. 같은 개념이다. 새 값이 오면 이전 내부 흐름을 취소하고 새 흐름으로 바꾼다. 검색처럼 "마지막 요청만 의미 있는" 경우에 쓴다.
  - Q. 디바운스 시간은 왜 300ms인가요? A. 사람이 연속으로 타이핑할 때 글자 사이 간격보다 길고, 입력을 멈춘 뒤 결과를 기다린다고 느끼기 전의 짧은 시간이라 흔히 쓰는 값이다. 측정 과제 T1·T3 결과를 보고 조정할 수 있다.
