# 01. 최소 서버와 서버 CI

- 무엇을 만들었나: `/health`만 있는 FastAPI 서버, 환경 변수로 읽는 설정(`Settings`), Docker 이미지, GitHub Actions 서버 CI(ruff → pytest).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 설정은 pydantic-settings의 `BaseSettings`로 읽는다. 환경 변수 이름이 필드 이름과 같고(대소문자 무시) 정수·불리언 변환을 알아서 해 준다. `os.environ`을 직접 읽으면 기본값과 타입 변환을 손으로 써야 한다.
  - 앱은 `create_app(settings)` 함수(앱 팩토리)로 만든다. 테스트가 키·한도를 바꾼 설정으로 앱을 새로 만들 수 있다. 모듈 수준 `app` 하나만 있으면 테스트마다 전역 설정을 고쳐야 한다.
  - Dockerfile의 CMD를 `sh -c`로 감쌌다. exec 형식(`["uvicorn", ..., "--port", "$PORT"]`)은 셸을 거치지 않아 `$PORT`가 글자 그대로 넘어가고, Render가 정해 주는 포트에 바인딩하지 못한다.
  - 테스트는 서버를 띄우지 않고 `httpx.ASGITransport`로 앱을 직접 호출한다. 포트가 필요 없고 빠르다.
- 막혔던 점과 해결:
  - 개발 PC에 Python 3.12가 없어 3.13으로 개발했다. `requires-python = ">=3.12"`라 설치는 되고, CI와 Docker는 3.12로 돌려 배포 환경과 맞춘다. ruff의 `target-version`을 `py312`로 두었고, 최종 확인은 CI가 한다.
  - 개발 PC에 Docker가 없어 이미지 빌드는 확인하지 못했다. 대신 CMD와 같은 `sh -c` 명령을 `PORT=9000`으로 실행해 그 포트에서 `/health`가 응답하는 것을 확인했다. 이미지 빌드는 Render 첫 배포에서 확인한다.
- 예상 면접 질문과 내 답:
  - Q. 설정을 왜 환경 변수로 받나요? A. 키 같은 비밀 값을 코드와 저장소에 남기지 않고, 같은 이미지를 로컬·Render·다른 호스팅에서 설정만 바꿔 쓰기 위해서다.
  - Q. `get_settings`에 `lru_cache`를 쓴 이유는? A. 요청마다 `.env` 파일과 환경 변수를 다시 읽지 않도록 한 번 만든 설정 객체를 재사용한다. 테스트는 이 함수를 거치지 않고 `create_app(test_settings)`로 설정을 직접 넣는다.
