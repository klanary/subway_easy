# 46. 카카오 경로 변환과 경로 API

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 카카오 대중교통 경로 응답을 서버 형식으로 바꾸는 `route_convert.py`, 카카오를 부르는 `KakaoRouteClient`, 캐시와 묶은 `RouteService`, `GET /v1/routes?from=&to=`.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 앱은 카카오 응답을 직접 보지 않는다. 서버가 단계마다 이동 수단, 시간, 경로선, 정차역을 정리하고, 지하철 단계에는 우리 역 id(`boardStationId`, `alightStationId`)를 붙인다. 이 id가 있어야 실시간 도착, 하차 알림, 탑승 감지가 같은 역을 가리킨다.
  - 카카오 좌표는 `[경도, 위도]` 순서다. 앱과 지도는 `(위도, 경도)`를 쓰므로 변환할 때 뒤집는다. 뒤집지 않으면 경로선이 바다에 그려진다. 모든 좌표가 한국 범위 안인지 테스트로 확인한다.
  - 첫 지하철 탑승 정보(`firstBoarding`)를 서버가 미리 계산해 준다. 탑승 전이 모두 도보인지, 역까지 몇 초인지가 승차 전 알림(⑦)의 출발 시각 계산에 쓰인다.
  - 같은 출발·도착은 10분 동안 캐시한다. 좌표는 소수점 4자리(약 10m)로 묶는다. 카카오 경로는 하루 1,000건이라 아껴 써야 한다.
- 막혔던 점과 해결:
  - 카카오도 실패를 HTTP 200으로 준다. 본문 `status`(`NO_RESULTS`, `EQUAL_POINTS` 등)를 보고 우리 오류 형식으로 바꾼다.
  - 같은 구간을 가는 버스가 여러 대면 차량 목록이 길게 온다. 화면에는 "5515 외 2대"처럼 줄여 보인다.
  - 환승 도보 단계에도 정차역 목록이 붙어 온다. 스펙상 도보 단계는 정차역이 없으므로 버린다.
  - 실제 응답의 정차역 이름("경복궁(정부서울청사)")이 역 데이터와 모두 맞는지, 실제 샘플 세 개로 테스트했다. 매칭 실패는 0건이었다.
- 예상 면접 질문과 내 답:
  - Q. 역 매칭에 실패하면? A. 그 단계의 역 id만 `null`로 두고 경로는 정상으로 돌려준다. 실패한 이름은 로그와 `/v1/metrics`의 `unmatchedStations`에 남겨 별칭으로 고친다.
  - Q. 출발지와 도착지가 같으면? A. 소수점 4자리까지 같으면 카카오를 부르지 않고 바로 400을 준다. 호출 한도를 아끼기 위해서다.
