# 28. 알림 채널, 진행 중 알림, 알림 버튼

- 무엇을 만들었나: 알림 채널 두 개(`session_ongoing`, `session_alerts`), 진행 중 알림(대기 단계는 "홍대입구 2호선 합정 방면 · 다음 열차 4분 · 7분 뒤 출발"과 [탑승했어요] [종료], 탑승 단계는 다음 하차 지점까지 시스템 카운트다운과 [종료]), 출발·하차 알림 문구, 알림 버튼을 받는 `SessionActionReceiver`.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 채널 중요도: 진행 중 알림은 낮음(소리 없이 알림창에만), 출발·하차 알림은 높음(화면 위에 뜨고 진동, 잠금 화면에도 내용 표시). Android 8부터 소리·진동은 알림 하나하나가 아니라 채널이 정한다.
  - 문구는 순수 함수(`ongoingContent`, `alertText`)로 떼어 기기 없이 테스트했다. `SessionNotifier`는 그 결과를 안드로이드 알림으로 옮기기만 한다. 앱 안 모드의 대화상자(Task 8)도 같은 `alertText`를 쓴다.
  - 남은 시간 표시: `setUsesChronometer` + `setChronometerCountDown` + `setWhen(하차 시각)`이면 시스템이 1초마다 다시 그린다. 앱이 매초 알림을 고칠 필요가 없어 배터리를 아끼고, 앱이 꺼져 있어도 숫자가 줄어든다.
  - 진행 중 알림은 id 1 하나를 계속 고쳐 쓰고 `setOnlyAlertOnce(true)`로 고칠 때마다 다시 울리지 않게 했다. 출발·하차 알림은 id 100부터 50개를 돌려 써서 연달아 와도 앞 알림을 덮지 않는다.
  - 알림 버튼은 `PendingIntent.getBroadcast`로 수신기를 부른다. 버튼마다 요청 코드(4001, 4002)와 동작 이름이 달라야 한다. 같으면 시스템이 같은 PendingIntent로 보고 덮어쓴다. Android 12부터는 `FLAG_IMMUTABLE`(또는 `FLAG_MUTABLE`)을 꼭 지정해야 한다.
  - 알람 수신기와 버튼 수신기가 같은 일(`goAsync` + 코루틴으로 컨트롤러 부르기)을 해서 `runWithSession` 하나로 묶었다.
  - `NotificationCompat` 대신 플랫폼 `Notification.Builder`를 썼다. 최소 SDK가 26이라 채널·카운트다운이 모두 플랫폼에 있고, 직접 선언하지 않은 라이브러리에 기대지 않아도 된다.
- 막혔던 점과 해결:
  - 첫 응답 전에도 "탈 수 있는 열차 정보가 없어요"가 보이는 문제: 서버가 깨어나는 데 1분 가까이 걸릴 수 있어 잘못된 안내가 된다. 아직 한 번도 갱신되지 않았으면(`updatedAt == null`) "열차 정보를 불러오고 있어요"를 보인다.
  - 하차 예정 시각이 지나면 카운트다운이 음수로 넘어가는 문제: 시각이 지나면 카운트다운을 끄고 "곧 도착해요"를 보인다.
  - Robolectric `ShadowNotificationManager`로 실제로 올라간 알림의 채널, 고정 여부, 버튼의 PendingIntent(요청 코드, 받는 쪽)까지 기기 없이 확인했다.
- 예상 면접 질문과 내 답:
  - Q. 이미 배포한 채널의 중요도를 바꾸려면? A. 채널은 한 번 만들면 앱이 중요도·소리를 바꿀 수 없다(사용자 설정이 우선). 새 id로 채널을 만들고 옛 채널을 지워야 한다.
  - Q. 진행 중 알림에서 남은 시간을 매초 갱신하지 않고 보이는 방법은? A. 크로노미터 카운트다운. 기준 시각만 넘기면 시스템 UI가 센다.
