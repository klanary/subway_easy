# 서울시 지하철 API 알려진 이슈 점검

서울 열린데이터광장 개발자 댓글(약 1년치)을 요약한 목록을 **2026-11-22 낮(11~12시) 실제 응답**으로 하나씩 대조했다.
분류 기준은 다음과 같다.

- **고친 이슈(원천)**: 지금 응답이 제대로 나온다. 옛날에 원천에서 고친 것으로 보고 따로 처리하지 않는다.
- **고친 이슈(우리)**: 지금도 재현되어 서버에서 처리했다.
- **여전함**: 원천에서 아직 고쳐지지 않았다. 앱은 대신할 방법으로 보인다.
- **미확인**: 확인할 수 없었다(시간대 등).

## 미확인

- **2호선 막차 표시(`lstcarAt`) 오류**: 막차 시간대에만 확인할 수 있다. 밤에 다시 본다.
- **신분당선 미래 `recptnDt`**: 서버는 미래 시각이면 지난 시간을 빼지 않는다(이미 처리). 이번 점검에서 다시 보지는 않았다.

## 아직 남은 우리 쪽 문제

- ~~실측 시간표가 낮에 다음 날 첫차("05:00 출발")를 다음 열차로 준다~~ → 고침. 원인: 실측 결과물(as_of 11-21)에 주말(요일 구분 2·3) 칸이 아직 없고, GTX-A 평일 6~24시는 변경 의심으로 빠져 있었다. 오늘 요일 칸이 없거나 앞으로의 시간대가 빠져 있으면 "모름"(빈 목록)으로 두고, 다음 날 첫차는 막차가 지난 밤에만 준다.
- 열차가 빠졌을 때 원본 응답을 남기는 기록이 없다.

## GTX-A 평일 실측이 빠졌던 일(2026-11-22)

- 원인: 11-20(금) GTX-A 하루 지연(서울역 상행 11시대 5~18분 늦음, 한 대 빠짐)을 밤 작업이 "변경 의심"으로 잡았고, 서버가 의심 단위를 통째로 뺐다. 11-16~19는 매일 같은 시각이었다.
- 처리: 서버는 의심 단위도 지난 실측 시각으로 낸다. 재학습 중인 단위만 뺀다.
- 남은 일: 판정 기준이 예민하다(4호선 출근 시간대 등 평소 지연도 "확정"됨). 기준값은 평일 15일치가 쌓인 뒤(12-07 이후) 맞춘다.

## 열차 위치 API(`realtimePosition`) 점검(2026-11-22)

위치 API는 앱·서버가 직접 쓰지 않는다. VM 수집기(`server/ml/`)가 실측 시간표와 변경 감지에 쓴다. 그래서 "지도 마커" 항목은 해당 없고, 같은 원천 문제가 실측 시간표를 비틀지 않는지 VM 수집 기록(원본 응답 14일 보관)으로 대조했다.

### 재현되어 고친 것(수집기, VM에 반영해야 효과가 난다)

| 이슈 | 재현 내용 | 처리 |
|---|---|---|
| 노선 전체·일부 열차 누락 | 11-16~22 07~21시 응답 가운데 106번이 그 시간대 대수의 절반 미만(9호선 56, 6호선 22, 신림선 16, 경춘선 10). 11-18 6호선 07:02~07:12는 연달아 INFO-200. 그 시간대가 정상 99/120으로 기준(96)을 넘겨 그대로 판정됐고, 6호선 07시 "변경 의심"이 났다. | 빈약한 응답(그 시간대 중앙값의 절반 미만)은 정상으로 세지 않고, 3분 넘게 연달아 빠진 시간대는 판정하지 않는다(`ml/points.py`). |

### 이미 맞게 다루고 있던 것

| 이슈 | 확인 |
|---|---|
| 열차번호 해석 | 번호는 원문 문자열로 두고 호선과 함께 쓴다. 첫 자리·홀짝으로 노선·방향을 정하지 않는다(방향은 `updnLine`). |
| 외부 역 목록 연결 | 위치 API `statnId`는 호선 + 역명으로 우리 역에 잇고(`index.resolve`), `statnId`를 따로 보관한다. |
| ITX `directAt = 9` | 경춘선에 실제로 온다(11-20 498행). 원래 값 그대로 저장하고, 급행이 지나가는 역 판정도 값별로 따로 한다. 다만 앱에는 "급행"으로 보인다. |
| 미래 `recptnDt` | 30초 넘게 미래면 표시(`future`)만 하고 지우지 않는다. |
| 이상 순간의 응답 기록 | 원본 응답 전체를 14일 보관한다(`raw_snapshots`). 이번 점검도 그것으로 했다. |

### 남은 것

- **01시 이후 수집 안 함**: 수집기는 01:00에 멈춘다. 00:50~00:59에도 2호선 190, 9호선 103건 등 이벤트가 있다. 관리자는 01시~첫차에도 보낸다고 했으므로, 01시 넘어 떠나는 막차는 실측에서 빠질 수 있다. 수집 시간을 늘리려면 VM 설정을 바꿔야 한다.
- 노선별 이슈(서해선 대곡~일산, 경춘선 청량리행 한 역 앞섬, GTX-A 대곡·킨텍스 방향, 진접선 위치)는 이번에 대조하지 않았다.
