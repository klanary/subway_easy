# 29. 하차 알림 시작 흐름과 통학 세션 화면

- 무엇을 만들었나: 경로 상세의 [출발(하차 알림)] 버튼, 첫 시작 때 권한 안내 → 알림 권한 요청 → "알람 및 리마인더" 안내로 이어지는 시작 흐름, 진행 중인 세션이 있으면 바꿀지 묻는 대화상자, 통학 세션 화면(머리글, [탑승했어요] [종료], 하차·환승 지점 목록, "알림이 늦을 수 있어요" 띠), 홈의 "통학 알림 진행 중" 배너, 알림을 누르면 세션 화면으로 가는 처리.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 권한은 앱을 처음 켤 때 한꺼번에 묻지 않고, 첫 세션을 시작할 때 이유를 먼저 설명한 뒤 요청한다(스펙 4.4). 맥락 없이 물으면 거절하기 쉽다. 거절하면 다시 조르지 않고 앱 안 모드로 시작한다.
  - 시작 방식 판단(`decideStart`)은 순수 함수로 떼어 기기 없이 테스트했다. 화면 쪽은 대화상자 순서만 맡는다.
  - 권한 요청 결과와 설정 화면에서 돌아오는 시점은 `rememberLauncherForActivityResult`의 콜백으로 받아 흐름을 이어 간다.
  - 머리글의 남은 분은 1초 시계(`stateIn(WhileSubscribed)`)로 다시 그린다. 보는 화면이 없으면 시계도 멈춘다. 홈 배너는 따로 떼어 배너만 다시 그리게 했다.
  - 알림을 누르면 `MainActivity`가 `onCreate`와 `onNewIntent`에서 동작 이름을 보고 요청을 넘기고, `AppNavHost`가 세션 화면으로 이동한다(`launchSingleTop`). Navigation 딥 링크는 `FLAG_ACTIVITY_NEW_TASK`가 붙은 인텐트를 받으면 액티비티를 다시 만들어 back stack을 새로 쌓기 때문에 쓰지 않았다.
  - 역 상세에서 시작한 세션은 이미 역에 있으므로 머리글을 "N분 뒤 OO행 열차가 도착해요"로 했다("지금 출발하면…"은 경로에서 시작한 경우만).
- 막혔던 점과 해결:
  - 이미 떠 있는 액티비티는 알림을 눌러도 `onCreate`가 다시 불리지 않는다(`SINGLE_TOP`). `onNewIntent`도 함께 처리해야 한다.
  - 도보만인 경로는 내릴 곳이 없어 [출발(하차 알림)] 버튼을 숨겼다.
- 예상 면접 질문과 내 답:
  - Q. 런타임 권한은 언제 요청하나? A. 그 기능을 처음 쓰는 순간, 이유를 먼저 보여 준 뒤. 거절해도 쓸 수 있는 대체 동작을 둔다.
  - Q. 화면 회전 때 알림 인텐트가 다시 처리되지 않게 하려면? A. `savedInstanceState == null`일 때만 처리한다. 회전·복원 때는 내비게이션 상태가 이미 복원된다.
