# 안드로이드 앱 화면 다듬기 2차: 템플릿 느낌 벗기 — 설계

- 날짜: 2026-11-21
- 범위: `android/app` UI 계층(`ui/**`, `ui/theme`, `ui/common`), 앱 아이콘 리소스, 글꼴 리소스. 서버·웹·데이터 계층은 범위 밖.
- 앞선 작업: 1차 "화면별 상태 다듬기"(`docs/superpowers/specs/2026-11-20-android-ui-state-polish-design.md`, develop `a0a50c4`). 1차가 만든 공통 상태 조각(`StateMessage`·`StateLoading`·`StaleNotice`)과 상태별 스크린샷 테스트(Roborazzi, `snapBothThemes`)를 그대로 쓴다.

## 1. 의도와 이유

1차로 모든 상태가 무언가를 보이게 됐지만, 사용자 평가는 "UI가 직관적이지 않고, 그래픽이 형편없다"이다. 앱 전체의 느낌(색, 글자 크기, 흐름)이 Material 3 기본 템플릿 그대로라는 것이 핵심 원인이다.

- 테마가 `lightColorScheme()` / `darkColorScheme()` 기본값이다(`ui/theme/Theme.kt`). 기본 보라 팔레트, 기본 글꼴, 기본 글자 크기.
- 앱 아이콘이 없어 실행할 때 기본 안드로이드 로고가 크게 나온다.
- 홈의 검색창·현재 위치·설정이 화면 맨 위에 있어 한 손으로 쓰기 어렵다.

이 앱은 **출근길에 한 손으로 빠르게 보는 도구**다(사용자 정의). 첫눈에 "몇 분 뒤 무슨 열차"가 읽히고, 자주 하는 동작은 엄지가 닿는 곳에 있어야 한다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 앱 전체에 하나의 시각 기준(색·글꼴·글자 크기·간격·모서리)을 세우고 모든 화면이 그것을 쓴다.
- 홈을 한 손 배치로 바꾼다(4.2).
- 화면마다 남은 "기본값 느낌"을 걷어 내고 위계를 분명히 한다(가장 중요한 숫자가 가장 크게).
- 앱 아이콘을 만든다.
- 라이트·다크 모두 같은 방향으로 보인다.

**비목표**
- 새 기능, 서버 API, 경로 탐색·알림 로직 변경.
- 노선도 SVG 다크 버전(1차에서 보류, 우선순위 낮음 — 여전히 보류).
- 웹 화면.

**반목표(이러면 실패)**
- 1차에서 만든 상태 동작(오류·오프라인·오래된 정보·다시 시도)이 깨지는 것. 기존 단위 테스트 404개는 계속 통과해야 한다.
- 색이 호선 색과 헷갈리는 것(색이 곧 정보인 앱이다).
- 다시 "보라색·그라데이션·과한 카드" 같은 기본 생성물 느낌으로 돌아가는 것.
- 한 손 배치가 지금 되는 일(검색, 현재 위치, 루틴·자주 가는 경로 열기, 출발·도착 고르기)을 한 번 더 누르게 만드는 것.

## 3. 제약

- 기존 한글 경로 빌드 설정(`android.overridePathCheck=true`, `-Dfile.encoding=UTF-8` 넣지 않음) 유지.
- 문구는 `ui/common/Copy.kt`, 해요체.
- 확인 수단: 상태별 스크린샷(라이트·다크, Pixel 8 폭) + 마지막에 에뮬레이터 `pixel8`로 전체 흐름 한 번(1차 A+B 방식).
- 진행 방식: 사용자가 원하는 대로 **질문은 한 번에 모아서**, 에뮬레이터 확인은 **마지막에 한 번**.
- 새 의존성은 글꼴 파일과 `androidx.core:core-splashscreen`(minSdk 26~30에서도 같은 시작 화면을 보이려고) 외에 추가하지 않는다.

## 4. 결정된 것(사용자 결정)

### 4.1 시각 방향: B "깔끔한 교통 도구"

흰 바탕·검정 글자. 색은 **호선 색과 강조색 하나**에만 쓴다. 남은 시간 숫자를 크고 굵게. 정보가 주인공이다. (비교한 다른 안: A 역 전광판 — 어두운 바탕·노란 숫자, C 따뜻하고 차분한 — 미색·주황·둥근 카드.)

### 4.2 홈 배치: 검색을 아래로(2번)

```
┌─────────────────────────┐
│                      ⚙ │  ← 설정만 위(오른쪽)
│   [출발·도착 고르는 중 띠] │  ← 있을 때만, 위
│                         │
│        노  선  도        │
│                         │
├─────────────────────────┤
│ ━━                      │
│ 🔍 어디로 갈까요?    [📍] │  ← 검색창 + 현재 위치(엄지 영역)
│ 08:10 통학 · 마포→공덕  › │  ← 오늘 루틴
│ ★ 홍대입구 → 잠실       › │  ← 자주 가는 경로
└─────────────────────────┘
```

- 검색창과 현재 위치 버튼을 아래 패널 맨 위로.
- 그 아래에 오늘 루틴과 자주 가는 경로를 **탭 없이 함께** 보인다(지금은 [루틴]/[자주 가는 경로] 탭 전환).
- 설정 아이콘만 위 오른쪽.
- **루틴 관리(사용자 결정):** 홈 패널에는 오늘 울릴 루틴 몇 줄만 보이고, [루틴 전체 보기]를 누르면 따로 열리는 **루틴 목록 화면**에서 관리한다(전체 목록, 켜기·끄기, 길게 눌러 삭제, 편집, "알림이 늦을 수 있어요"·[설정 열기]). 지금의 `RoutineListContent`를 그 화면으로 옮긴다.
- **오늘 루틴 줄을 누르면(사용자 결정):** 그 루틴 경로의 **경로 결과를 바로** 연다(자주 가는 경로와 같은 동작). 편집은 루틴 목록 화면에서.
- **진행 중 알림 띠:** 엄지 영역 원칙에 따라 아래 패널 바로 위에 붙인다. 출발·도착 고르는 중 띠는 위에 둔다(지도 위 상태 표시라서).
- (비교한 다른 안: 1 지금 구조 유지, 3 전부 아래 한 줄 + 메뉴.)

### 4.3 강조색: 신호 파랑

주 버튼, 선택된 칩, 진행 중 알림에 쓴다. 1호선(`#0052A4`)과 구분되게 밝은 파랑 `#2F5BEA`(라이트). 호선 배지에는 항상 호선 이름 글자가 있어 색만으로 구분하지 않는다.

### 4.4 진행 방식: 기준 먼저, 그다음 화면별(1번)

## 5. 접근 방식

| 방식 | 내용 | 장단점 |
|---|---|---|
| **1. 기준 먼저, 그다음 화면별 (선택)** | 색·글꼴·크기·간격·모서리를 테마 기준으로 먼저 넣고, 홈 배치와 화면별 손질을 한 번에 합의해 반영 | 일관성이 가장 좋고, 테마만으로 전 화면 느낌이 한꺼번에 바뀜 |
| 2. 화면마다 따로 손질 | 기준 없이 화면별로 모양 잡기 | 빨리 시작하지만 화면마다 어긋나 다시 템플릿 느낌으로 돌아가기 쉬움 |
| 3. 전체를 목업으로 먼저 설계 | 브라우저 목업으로 모든 화면 확정 후 구현 | 미리 다 보이지만 두 번 일함, 가장 오래 걸림 |

## 6. 시각 기준 (검토안)

### 6.1 색

| 역할 | 라이트 | 다크 |
|---|---|---|
| 바탕(background) | `#F6F7F9` | `#0E1116` |
| 면(surface: 카드·시트·패널) | `#FFFFFF` | `#171B22` |
| 옅은 면(surfaceVariant: 칩·입력) | `#F1F2F4` | `#232833` |
| 선(outline) | `#E6E8EC` | `#2C3340` |
| 글자(onSurface) | `#111418` | `#F2F4F7` |
| 보조 글자(onSurfaceVariant) | `#5B6472` | `#9AA3AF` |
| 강조(primary) | `#2F5BEA` | `#7C9BFF` |
| 강조 위 글자(onPrimary) | `#FFFFFF` | `#0B1B4D` |
| 강조 옅은 면(primaryContainer) | `#E8EEFF` | `#1F2E66` |
| 그 위 글자(onPrimaryContainer) | `#1E3FB0` | `#DCE4FF` |
| 오류(error) | `#D92D20` | `#FF6B6B` |
| 주의(오래된 정보·근거 표식, tertiary) | 글자 `#B54708` / 면 `#FEF0C7` | 글자 `#FDB022` / 면 `#3D2A0A` |

- 보조 글자는 흰 바탕에서 4.5:1 이상(WCAG AA)을 맞춘다.
- 호선 색은 `LineColors.kt` 그대로. 배지 글자색은 1차에서 만든 밝기 기준(`badgeTextColor`) 유지.

### 6.2 글꼴과 글자 크기

- 글꼴: **Pretendard**(SIL OFL, 한글 가독성). 4가지 굵기(Regular·Medium·SemiBold·Bold)를 `res/font`에 넣는다. 용량을 줄이려면 KS X 1001 범위로 줄인 판(Pretendard Std 등)을 쓴다.
  - **글꼴 파일은 인터넷에서 내려받아야 한다.** 구현 때 파일 이름·출처·용량을 밝히고 사용자 허락을 받은 뒤 받는다. 허락이 없으면 시스템 글꼴로 두고 나머지 기준만 적용한다.
- 숫자는 폭 고정(tabular figures)으로, 남은 분이 바뀌어도 줄이 흔들리지 않게.
- 크기 단계(sp):

| 이름 | 크기/굵기 | 쓰는 곳 |
|---|---|---|
| 큰 숫자 | 32 / Bold | 남은 시간, 경로 총 시간, 알림 대기 시간 |
| 제목 | 22 / Bold | 역 이름, 화면 제목 |
| 소제목 | 17 / SemiBold | 단계 줄, 카드 머리 |
| 본문 | 15 / Regular | 일반 글 |
| 보조 | 13 / Regular | 방면·정거장·설명 |
| 라벨 | 12 / SemiBold | 배지, 칩, 표식 |

### 6.3 간격·모서리·그림자

- 간격 단계: 4 · 8 · 12 · 16 · 24 dp. 화면 좌우 여백 16dp.
- 모서리: 카드·시트 16dp, 버튼·입력 14dp, 칩·배지 완전 둥근(pill).
- 그림자 대신 얇은 선(outline)으로 면을 나눈다(B 방향). 떠 있는 것(아래 패널, 스낵바)만 옅은 그림자.
- 카드 안에 카드를 넣지 않는다.
- 터치 영역 최소 48dp.

### 6.4 앱 아이콘

- 적응형 아이콘(벡터). 신호 파랑 바탕에 흰색 단순 표지(예: 열차 앞모습 + 출발 화살표). 두 시안을 비교한 뒤 선택한다.
- 시작 화면(스플래시)도 같은 아이콘·바탕색. 매니페스트 테마가 지금 `Theme.Material.Light.NoActionBar`라 다크 모드에서도 흰 화면으로 시작하므로, 라이트·다크를 따르는 시작 테마로 바꾼다.

## 7. 진행 방식

0. **준비:** 브랜치 `polish2/0-theme`. 바뀌기 전 스크린샷 기준 이미지를 비교용으로 남긴다.
1. **테마 기준:** 6.1~6.3을 `ui/theme`에 넣는다(색 구성, 글꼴, 크기 단계, 모양, 간격 상수). 화면 코드에 흩어진 기본 스타일 사용(`headlineSmall`을 큰 숫자에 쓰는 곳 등)을 기준 이름으로 바꾼다. 전 화면 스크린샷을 다시 찍어 전후를 보인다.
2. **앱 아이콘:** 두 안을 만들어 보이고 고른다.
3. **홈 배치(4.2):** 노선도 홈을 한 손 배치로 바꾼다.
4. **화면별 손질 — 한 번에 합의:** 역 시트, 검색, 경로 편집·결과·상세, 루틴, 알림, 설정을 새 기준으로 찍어 한꺼번에 보이고, 화면마다 고칠 점을 한 번에 묻는다(1차 A 방식). 합의한 것을 반영한다.
5. **마지막 확인:** 에뮬레이터로 처음부터 끝까지 한 번(1차 B 방식), 라이트·다크 모두. 최종 검토자 한 번.
6. 사용자가 확인하면 `develop`에 합친다. 푸시는 사용자가 요청할 때만.

질문은 2단계(아이콘)와 4단계(화면별)에서 모아서 한다. 1단계는 이 문서로 정해진 값을 넣고 결과만 보인다.

## 8. 정해진 것 / 빌더에게 맡기는 것

**사용자 결정:** 4.1~4.4.

**세부 결정 사항(변경 가능):** 6장의 구체 값 전부, Pretendard 선택, 아이콘 방향, 7장의 순서.

**빌더에게 맡기는 것**
- 테마 기준을 코드로 담는 구조(`MaterialTheme` 확장, 별도 토큰 객체 등).
- [경로 찾기] 버튼의 정확한 위치(홈 아래 패널 안, 한 손으로 닿는 곳이어야 함).
- 홈 아래 패널의 접힘·펼침 높이와 오늘 루틴·자주 가는 경로를 몇 줄까지 보일지(넘치면 "더 보기").
- 화면별 세부는 4단계 합의에서 정한다.

## 부록: 1차에서 넘어온 미뤄 둔 문제

**범위:** UI 항목만 이번에 넣는다 — 상세 문구 중복, 오래된 정보 띠 터치 영역 48dp, 다크 노선도 저장본 흰 여백, 큰 글꼴 칩 넘침, 설정에서 권한 끄러 가는 길. 나머지(저장 원자성, 회전 뒤 위치, 메인 스레드 읽기, 긴 오류 문구 스크롤)는 UI 계층 범위 밖이라 이번에 하지 않는다.

- 경로 상세의 서버 안내 문구가 새 단계 줄과 중복("1호선 (시청 > 종로3가)").
- "정보가 늦어지고 있어요" 띠 터치 영역 약 36dp(48dp 미만).
- 다크 모드 노선도 저장본의 흰 여백 번쩍임.
- 역 시트 시각 칩이 큰 글꼴에서 넘칠 수 있음.
- 설정에서 허용된 권한을 끄러 갈 길이 없음.
- 저장 파일 쓰기 원자성, 회전 뒤 위치, 메인 스레드 41바이트 읽기, 긴 오류 문구 스크롤.
