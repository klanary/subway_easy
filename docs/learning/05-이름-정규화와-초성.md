# 05. 역·호선 이름 정규화와 초성 검색

- 무엇을 만들었나: 역 이름 정규화(`normalize_station_name`: 공백 정리 → 괄호 별칭 분리 → 끝의 "역" 제거), 호선 이름 정규화(`normalize_line`), 서울시 `subwayId` → 호선 표, 한글 초성 변환(`to_chosung`)과 초성 검색어 판별(`is_chosung_query`), 두 좌표 사이 거리(`haversine_m`).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 서울시 역사마스터, 서울시 실시간 API, 카카오 경로가 같은 역·호선을 다르게 적는다("홍대입구역"/"홍대입구", "수도권 2호선"/"2호선"). 비교하기 전에 모두 같은 규칙으로 바꿔야 매칭된다. 빌드 스크립트와 서버가 같은 함수를 써서 규칙이 어긋나지 않게 했다.
  - 규칙 순서는 1 → 3 → 2다. "가나역(다라역)"에서 끝의 "역"을 먼저 지우려 하면 끝 글자가 ")"라 지워지지 않는다. 괄호를 먼저 떼면 "가나역" → "가나"가 된다.
  - 초성은 유니코드 산술로 구한다. 한글 음절은 `0xAC00 + (초성×21 + 중성)×28 + 종성`으로 배치돼 있어 `(코드 − 0xAC00) // 588`이 초성 번호다. 초성 표를 따로 저장하지 않아도 된다.
  - 거리 계산은 하버사인 공식이다. 역 사이 거리(수 km) 범위에서 충분히 정확하고 외부 라이브러리가 필요 없다.
- 막혔던 점과 해결:
  - 계획의 순서대로만 하면 "수도권 분당선"처럼 접두어 뒤에 별칭이 오는 표기는 "분당선"으로 남는다. 접두어를 뗀 뒤 별칭 표를 한 번 더 확인하게 했다.
  - "(이수)"처럼 괄호 앞이 빈 이름은 빈 id가 됐다. 테스트로 재현한 뒤, 괄호 앞이 비면 나누지 않게 고쳤다(빈 id는 역 표의 기본 키가 되므로 충돌한다).
- 예상 면접 질문과 내 답:
  - Q. 초성 검색은 어떻게 구현했나요? A. 역 이름의 초성 문자열을 빌드 때 미리 계산해 두고(`chosung` 열), 검색어가 모두 자음이면 그 열에서 찾는다. 초성은 유니코드 한글 음절의 배치 규칙으로 계산한다.
  - Q. 이름 매칭이 실패하면? A. 별칭 표에 추가해 해결하고, 실패한 이름 수를 `/v1/metrics`의 `unmatchedStations`로 보여준다(P2 Task 11).
