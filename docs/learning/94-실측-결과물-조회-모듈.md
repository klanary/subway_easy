# 94. 실측 결과물 조회 모듈

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: `server/app/services/measured.py`. VM이 만든 실측 시간표(B1)와 구간 시간(B2) JSON을 읽어 세 가지를 답한다. 그 역의 다음 출발들, 열차 번호로 다른 역 시각 찾기, 이웃 두 역 사이 이동 시간.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 받기와 조회를 나눴다. 조회는 외부 호출 없는 순수 코드라 작은 픽스처로 빠르게 테스트한다(12개, 0.04초).
  - 결과물을 읽을 때 한 번 색인을 만든다((요일 구분, 호선, 방향, 역) → 시각 목록). 요청마다 JSON을 훑지 않는다.
  - 변경 의심 중인 단위는 서버가 다시 거른다. B1이 이미 관측 일수 하한을 걸러도, 시각이 바뀌는 중인 칸은 틀릴 수 있다.
- 막혔던 점과 해결:
  - 실측 시각은 "운행일 0시부터 초"라 24시를 넘으면 86400 이상이다. 운행일 0시에 그대로 더하면 다음 날 00:20이 자연스럽게 나온다.
  - 2호선과 신분당선은 같은 열차 번호가 날마다 다른 시각에 다닌다(±5분 일치 57%, 21%). 이 노선은 B1이 번호 없이 묶으므로 "열차 번호로 다른 역 시각"은 None을 돌려준다.
- 예상 면접 질문과 내 답:
  - Q. 왜 결과물을 DB가 아니라 메모리에 두나?
  - A. 수 MB 크기이고 읽기만 하며 주 2회 바뀐다. 무료 서버 한 대에서는 메모리 색인이 가장 단순하고 빠르다. 커지면 SQLite 파일로 바꾸면 된다.
