# 17. 경로 편집 화면과 경로 흐름 상태

- 무엇을 만들었나: 출발·도착 칸, [현재 위치] 칩, 출발↔도착 바꾸기, [경로 검색]이 있는 경로 편집 화면과, 경로 편집·결과·상세 세 화면이 함께 쓰는 `RouteFlowViewModel`(출발·도착, 검색 결과, 받은 시각, 고른 경로).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 세 화면이 같은 출발·도착과 검색 결과를 보므로 ViewModel 하나를 중첩 그래프(`RouteFlowGraph`)의 back stack entry에 붙여 공유한다. 결과를 화면 인자로 넘기면 큰 경로 목록을 직렬화해야 하고, 화면끼리 상태가 어긋날 수 있다. 그래프를 벗어나면(홈으로 돌아가면) ViewModel도 함께 사라진다.
  - 출발 기본값은 현재 위치다(스펙 3.1 ②). 권한이 없거나 5초 안에 위치를 못 얻으면 출발 칸을 비우고 "출발지를 검색하거나 현재 위치를 허용해 주세요"를 보여준다. 위치를 기다리는 사이 사용자가 출발지를 고르면 늦게 온 현재 위치가 덮어쓰지 않는다.
  - 홈 검색창으로 들어와 도착이 비어 있으면 곧바로 검색 화면을 연다. 이 "자동 열기"는 처음 한 번만이다. 검색에서 그냥 돌아왔을 때 또 열리면 경로 편집 화면을 벗어날 수 없다.
  - 출발·도착이 바뀌면 이전 검색 결과를 지운다. 바뀐 지점과 맞지 않는 결과가 남아 있지 않게 한다.
  - 검색 결과를 받은 시각(`receivedAt`)을 저장한다. 서버의 남은 초(`remainingSec`)는 응답 시점 기준이라, 화면은 이 시각을 더해 도착 예정 시각으로 바꿔 쓴다(스펙 6.2).
- 막혔던 점과 해결:
  - `appViewModel`에 ViewModel 주인(`ViewModelStoreOwner`)을 넘길 수 있게 바꿨다. 기본값은 지금 화면이고, 중첩 그래프 entry를 넘기면 공유된다.
- 예상 면접 질문과 내 답:
  - Q. 화면 간 데이터 전달 방법을 어떻게 골랐나요? A. 작은 값(역 id 등)은 내비게이션 인자로, 이전 화면에 돌려주는 선택 결과는 SavedStateHandle로, 여러 화면이 함께 보는 상태는 중첩 그래프에 붙인 ViewModel로 나눴다.
