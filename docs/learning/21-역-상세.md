# 21. 역 상세 실시간 도착과 역 즐겨찾기

- 무엇을 만들었나: 역 상세 화면. 호선·방향(·방면)별로 다음 열차 2대의 행선지와 남은 시간, 급행·막차 표시, "n초 전 갱신", 역 즐겨찾기[★]. 화면이 보이는 동안만 30초마다 서버에 다시 묻는다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 자동 갱신은 ViewModel의 `suspend fun runAutoRefresh()`(갱신 → 30초 대기 반복)를 화면이 `repeatOnLifecycle(STARTED)` 안에서 부른다. 앱을 내리거나 다른 화면으로 가면 코루틴이 취소돼 갱신이 멈추고, 돌아오면 다시 시작한다. ViewModel 안에서 무한 루프를 돌리면 화면이 안 보여도 서울시 API 한도를 계속 쓴다.
  - 서버는 30초에 한 번 묻지만 화면의 남은 시간은 1초마다 줄어든다. 응답을 받은 시각을 저장하고, 지금까지 지난 시간을 빼서 보여준다(`displayRemainingSec`). 0 아래로는 내려가지 않는다.
  - 서버가 만료 캐시로 응답하면(`stale`) 흐리게 "갱신 지연"을, 운행이 끝난 시간처럼 그룹이 없으면 "도착 정보가 없어요"를 보여준다(스펙 4.5).
- 막혔던 점과 해결:
  - 30초 반복을 실제로 기다리지 않으려고 가상 시간으로 60초를 앞당겨 호출이 3번(0초·30초·60초)인지, 취소 뒤에는 더 늘지 않는지 테스트했다.
  - 개발 PC에 기기와 배포된 서버가 없어 "홈으로 나가면 갱신이 멈춘다"는 서버 접근 로그 확인은 하지 못했다.
- 예상 면접 질문과 내 답:
  - Q. `repeatOnLifecycle`과 `LaunchedEffect`만 쓰는 것의 차이는? A. `LaunchedEffect`는 화면이 구성에 남아 있는 동안 계속 돈다. 앱이 백그라운드로 가도 Compose 구성은 남아 있을 수 있어 갱신이 계속된다. `repeatOnLifecycle(STARTED)`는 생명주기가 STARTED 아래로 내려가면 블록을 취소하고 다시 올라오면 새로 시작한다.
