# 02. 외부 API 샘플 수집

- 무엇을 만들었나: 외부 API 4종(서울시 실시간 도착, 카카오 키워드 검색·좌표→주소, 카카오 대중교통 경로)의 실제 응답을 `server/tests/fixtures/`에 저장하는 스크립트(`scripts/capture_fixtures.py`)와 그 테스트, 외부 API 주소 상수(`app/clients/endpoints.py`).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 테스트 중에는 실제 외부 API를 부르지 않는다(스펙 9.1). 대신 실제 응답을 한 번 저장해 두고 테스트에서 돌려준다. 문서만 보고 손으로 만든 응답은 실제 필드 이름이나 값 형식과 어긋날 수 있다.
  - 샘플은 `{"status": HTTP 상태 코드, "body": 응답}` 형식이다. 상태 코드까지 있어야 오류 흐름(카카오 오류 코드 → 서버 오류)을 실제 응답으로 재현할 수 있어서, 오류 응답도 그대로 저장한다.
  - 저장 전에 키 문자열을 `***`로 바꾼다(`redact`). 서울시 키는 URL 경로에 들어가므로 오류 메시지에 섞여 나올 수 있다.
  - 좌표는 `LANDMARKS`의 공공 장소만 쓰고, 테스트(`test_capture_plan_uses_only_public_landmarks`)가 이를 강제한다. 공개 저장소에 집·학교 좌표가 남으면 생활 반경이 드러난다.
- 막혔던 점과 해결:
  - 카카오 경로 API 주소는 문서로 확인하기 전이라 비워 두었고, 비어 있으면 경로 항목을 건너뛰며 이유를 출력한다. 키가 비어 있을 때도 항목마다 이유를 출력하고 넘어간다.
- 예상 면접 질문과 내 답:
  - Q. 외부 API를 테스트에서 어떻게 다루나요? A. 실제 응답을 저장해 두고, 테스트에서는 respx로 httpx 요청을 가로채 그 샘플을 돌려준다. 테스트 결과가 네트워크 상태, 키, 호출 한도에 영향을 받지 않는다.
  - Q. 키가 저장소에 들어가지 않게 어떻게 했나요? A. 키는 `.env`(git 무시 대상)와 호스팅 환경 변수에만 두고, 샘플은 저장하기 전에 키 문자열을 가린다. 커밋 전에 `git grep`으로 키 문자열이 없는지 한 번 더 확인한다.
