# 97. 수·일 실측 결과물을 GitHub 릴리스로 내보내기

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: `server/ml/publish.py`와 `subway-ml-publish` 타이머(수·일 03:30). 최근 7일로 구간 시간을 만들고, 실측 시간표와 함께 gzip해 릴리스 자산을 바꾼다. manifest는 마지막에 올린다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - GitHub 릴리스를 골랐다(사용자 결정). 무료이고, 저장소가 공개라 서버는 토큰 없이 받는다. Azure 저장소는 계정을 새로 만들어야 하고, 커밋은 매번 Manual Deploy가 필요했다.
  - 구간 시간을 호선마다 따로 만들어 합친다. VM 메모리가 1GB라 7일치 이벤트를 한 번에 올리면 위험하다.
  - 토큰은 헤더로만 보내고, 로그에는 상태 코드와 파일 이름만 남긴다.
- 막혔던 점과 해결:
  - `setup_vm.sh`의 유닛 목록에 글자 그대로의 백슬래시와 n이 들어가 있었다(앞선 작업). bash는 이것을 `n`이라는 유닛으로 읽고 `set -e` 때문에 설치가 멈춘다. 루프의 유닛 이름이 모두 파일로 있는지 보는 테스트를 더하고 고쳤다.
- 예상 면접 질문과 내 답:
  - Q. 올리는 도중 서버가 받으면?
  - A. 데이터 파일이 먼저 바뀌어도 manifest의 sha256과 맞지 않아 서버는 지난 것을 쓴다. manifest가 마지막에 바뀐 뒤에야 새 것을 받는다.
