# 09. 열차 남은 시간 계산과 안내 문구 해석

- 무엇을 만들었나: 서울시 실시간 도착 응답의 열차 한 대에서 "남은 초"를 구하는 `compute_remaining_sec`, 이미 떠난 열차 판별(`is_departed`), "OO행 - XX방면" 분리(`parse_train_line_nm`), 급행·막차 판별.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 도착 예정 초(`barvlDt`)는 서울시 서버가 데이터를 만든 시각(`recptnDt`) 기준이다. 캐시(20초)와 전달 지연 때문에 그대로 쓰면 실제보다 길게 보이므로, 지난 시간을 빼서 "지금 기준"으로 맞춘다.
  - `barvlDt`가 0이면 안내 문구로 추정한다. 문구는 "전역 진입"처럼 다른 패턴("진입")을 포함하는 경우가 있어, 구체적인 패턴부터 차례로 검사한다(전역 → 분·초 → 분 → 진입·도착).
  - "OO 출발"은 이미 이 역을 떠난 열차라 목록에서 뺀다. "전역 출발"은 아직 오는 중이므로 남긴다.
  - 추정 상수(전역 출발 90초 등)는 실제 로그로 보정할 값이라 상수로 모아 두었다.
- 막혔던 점과 해결:
  - 실제 샘플로 모든 문구가 해석되는지 확인하는 테스트는 샘플이 있어야 돌 수 있다. 샘플 수집 전에는 건너뛰고, 샘플이 생기면 자동으로 실행되게 `skipif`를 걸었다.
  - "행신행 - 강매방면"처럼 역 이름에 "행"이 들어가도 `(.+?)행\s*-` 패턴이 " -" 바로 앞의 "행"에서 끊어 "행신"을 바르게 뽑는다.
- 예상 면접 질문과 내 답:
  - Q. 남은 시간이 실제와 다르면? A. 추정 상수는 실측 로그로 보정하고 보정 이력을 학습 노트에 남긴다. 앱은 응답을 받은 시각에 남은 초를 더해 도착 예정 시각으로 바꿔 카운트다운하므로, 서버 지연이 화면에 누적되지 않는다.
