# 03. 안드로이드 뼈대와 카카오 지도 실험

- 무엇을 만들었나: Kotlin·Jetpack Compose 앱 뼈대(패키지 `io.github.klanary.jigeumchulbal`, minSdk 26, compileSdk·targetSdk 36), `local.properties`에서 서버 주소·지도 키를 읽는 `BuildConfig` 필드, 카카오 지도에 경로선 1개를 그리는 실험 화면(`map/MapExperiment.kt`), 앱 CI(`testDebugUnitTest assembleDebug`).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 서버 주소와 카카오 네이티브 앱 키는 커밋하지 않는 `local.properties`에서 읽어 `BuildConfig`로 넣는다. 값이 없으면 더미 값으로 빌드되므로 키가 없는 CI에서도 빌드·테스트가 통과한다.
  - 라이브러리 버전은 `gradle/libs.versions.toml` 한 곳에서 정한다. P3·P4가 쓸 Retrofit·Room·DataStore 등도 미리 적어 두어 버전이 흩어지지 않게 했다.
  - 카카오 지도 SDK v2는 View 기반이라 Compose의 `AndroidView`로 감쌌다. 화면 생명주기의 ON_RESUME·ON_PAUSE를 `MapView.resume()`·`pause()`에 연결해, 화면이 안 보일 때 지도 렌더링을 멈춘다.
  - 지도 초기화에 실패하면(`onMapError`) 지도 대신 원인 문구를 보여준다. 키가 잘못돼도 앱이 죽지 않는다(스펙 4.5).
- 막혔던 점과 해결:
  - 프로젝트 경로(`vscode 모음`)에 한글이 있어 AGP가 "non-ASCII characters" 오류로 빌드를 거부했다. `gradle.properties`에 `android.overridePathCheck=true`를 넣어 검사를 껐다.
  - 그다음 단위 테스트가 `ClassNotFoundException: BuildConfigTest`로 실패했다. 테스트 클래스는 컴파일돼 있었다. 원인은 Gradle 데몬 옵션 `-Dfile.encoding=UTF-8`이었다. 데몬은 테스트 JVM에 넘길 클래스패스를 인자 파일에 UTF-8로 쓰는데, Windows의 java 실행기는 그 파일을 시스템 코드 페이지(CP949)로 읽어 한글 경로가 깨졌다. 옵션을 빼자 통과했다(가설 → 옵션 하나만 바꿔 확인).
  - 경로 샘플(`kakao_route_subway_only.json`)은 카카오 키가 있어야 수집할 수 있어, 실험 경로는 2호선 홍대입구~강남 사이 공공 역 좌표로 대신했다. 샘플을 수집하면 바꾼다.
- 예상 면접 질문과 내 답:
  - Q. 지도 키를 앱에 넣으면 노출되지 않나요? A. 네이티브 앱 키는 앱 안에 들어갈 수밖에 없다. 대신 카카오 콘솔에 등록한 패키지명과 서명 키 해시로 사용처가 제한된다. 서버용 REST 키는 앱에 넣지 않고 서버에만 둔다.
  - Q. Compose에서 View 기반 지도를 어떻게 썼나요? A. `AndroidView`로 감싸고, `remember`로 MapView를 한 번만 만들며, `DisposableEffect`에서 생명주기 관찰자를 등록·해제했다.
