# 23. 설정 화면 (내 장소, 알림 시점, 권한, 출처)

- 무엇을 만들었나: 설정 화면과 `SettingsViewModel`. 내 장소(집·학교·회사·직접 추가)를 검색이나 지도로 지정·삭제, 알림 시점 네 항목(출발 여유 시간, 하차·환승 알림, 역 상세 승차 전 알림, 최대 대기 시간)을 정해진 선택지에서 고르기, 위치·알림·정확한 알람 권한 상태와 [설정 열기], 앱 버전과 데이터 출처(스펙 10.4).
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 알림 시점은 자유 입력 대신 선택지(예: 하차 알림 1·2·3·4분 전)로 받는다. 이상한 값(0초 전, 1시간 전)이 들어갈 일이 없고, 선택지 밖 값은 ViewModel이 거부한다(`IllegalArgumentException`).
  - 검색·지도 화면에서 돌아온 위치를 어느 종류(집·학교…)로 저장할지는 `rememberSaveable`로 기억한다. 검색 화면으로 가 있는 동안 설정 화면이 구성에서 빠져도 값이 남는다.
  - 권한 행은 그 기기에 해당하는 것만 보인다. 알림 권한은 Android 13부터, 정확한 알람 권한은 12부터 있다. 설정 앱에서 권한을 바꾸고 돌아오면(`LifecycleResumeEffect`) 상태를 다시 읽는다.
- 막혔던 점과 해결:
  - 다른 테스트(`toggleFavorite`)가 "테스트 시작 전에 잡히지 않은 예외"로 실패했다. 원인은 설정 ViewModel 테스트가 쓰는 임시 파일 DataStore였다. IO 스레드에서 늦게 값을 내보냈는데, 그때는 테스트가 끝나 Main 디스패처가 해제돼 있었다. ViewModel 테스트에는 메모리 DataStore를 쓰고, 파일 저장 자체는 저장소 테스트(14번)가 확인하게 나눴다. 전체 테스트를 세 번 연속 돌려 다시 나지 않는 것을 확인했다.
  - 데이터 이용허락 문구는 P1에서 원본 데이터를 내려받은 뒤(api-verification §2) 정보 화면에 더한다.
- 예상 면접 질문과 내 답:
  - Q. 테스트 하나가 다른 테스트를 깨뜨리면 어떻게 찾나요? A. 실패한 테스트의 예외 안에 숨은 원래 예외(suppressed, caused by)를 끝까지 읽는다. 이번에는 "Dispatchers.IO에서 끝난 코루틴이 해제된 Main에 접근"이라는 단서로, 테스트 밖으로 새는 비동기 작업을 찾았다.
