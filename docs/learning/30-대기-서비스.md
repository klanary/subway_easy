# 30. 대기 포그라운드 서비스와 승차 전 알림

- 무엇을 만들었나: 대기 단계(⑦) 동안 30초마다 실시간 도착을 받아 세션에 넘기는 `WaitingPoller`, 그것을 진행 중 알림과 함께 돌리는 포그라운드 서비스 `WaitingService`(유형 `dataSync`), 경로·역 묶음에서 기다릴 대상을 만드는 `WaitTargets`, 경로 상세와 역 상세의 [승차 전 알림] 버튼.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 대기 단계는 앱이 꺼져 있어도 30초마다 서버를 불러야 해서 포그라운드 서비스가 필요하다. `WorkManager`의 주기 작업은 최소 15분이라 맞지 않는다. 탑승 단계는 내릴 시각이 이미 정해져 있어 알람만으로 충분하므로 서비스를 쓰지 않는다(배터리).
  - 조회 반복은 안드로이드와 떼어 순수 Kotlin(`WaitingPoller`)으로 만들고 가상 시간으로 테스트했다. 60초 동안의 동작을 몇 밀리초에 확인한다. 앱 안 모드(Task 8)도 같은 폴러를 쓴다.
  - `startForegroundService` 뒤 몇 초 안에 `startForeground`를 부르지 않으면 앱이 죽는다. 그래서 세션 상태를 보기 전에 먼저 부른다.
  - 경로에서 시작할 때 첫 탑승 전이 모두 도보면 출발 시각을 계산하고, 버스가 끼면 도착 시각을 예측할 수 없어 "도착 N분 전" 방식으로 대신한다(스펙 4.3).
- 막혔던 점과 해결:
  - 서비스 알림과 진행 중 알림이 같은 id(1)를 쓴다. 서비스가 멈추면 시스템이 그 id의 알림을 지우는데, [탑승했어요]로 탑승 단계에 들어가며 같은 id에 쓴 하차 카운트다운 알림까지 사라질 수 있다. 서비스가 끝날 때 `STOP_FOREGROUND_DETACH`로 알림을 서비스에서 떼어 낸 뒤 지금 세션 상태로 다시 맞췄다(끝났으면 지운다).
  - lint 경고 두 개: `stopService`에 새 인텐트를 넘긴다는 경고는 인텐트 하나를 같이 쓰게 바꿨고, API 29부터 있는 서비스 유형 상수는 버전 분기로 감쌌다.
- 예상 면접 질문과 내 답:
  - Q. Android 14에서 포그라운드 서비스는 무엇이 바뀌었나? A. 매니페스트에 유형(`foregroundServiceType`)을 선언하고 유형별 권한(`FOREGROUND_SERVICE_DATA_SYNC`)을 받아야 한다. Android 15부터 `dataSync`는 하루 6시간 제한이 있어 최대 대기 시간(기본 30분)을 둔 것과도 맞는다.
  - Q. 네트워크가 끊기면? A. 실패한 조회는 무시하고 마지막 예측으로 예약한 알람이 그대로 울린다. 3번 연속 실패하면 진행 중 알림에 "실시간 정보 연결 끊김"을 보인다.
