# 60. 루틴 실행과 루틴 화면

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 루틴 알람이 울리면 `RoutineReceiver` → `RoutineRunner`가 다음 실행을 다시 예약하고, 저장한 경로로 "지금 출발하세요" 세션(출발 타이밍 방식, 걷는 시간 = 루틴의 걷는 시간, 진동 알림 = 루틴 설정)을 시작한다. 진행 중인 세션이 있으면 건너뛰고 "진행 중인 통학 알림이 있어 루틴을 건너뛰었어요"를 알린다. 재부팅·앱 업데이트·시간·시간대 변경 때 모든 루틴을 다시 예약한다. 화면: 루틴 등록·편집(요일, 시각, 걷는 시간 0~30분, 진동 알림, "이 시각에 타게 될 열차" 미리보기), 노선도 패널의 루틴 목록(켜기·끄기, 길게 눌러 삭제, 정확한 알람 권한이 없으면 안내 띠), 경로 상세의 [루틴으로 만들기].
- 왜 이렇게 했나:
  - 세션은 한 번에 하나다. 루틴이 진행 중인 통학 알림을 끊지 않는다.
  - 루틴을 켜려면 알림 권한이 필요하다. 없으면 요청하고, 거부하면 꺼진 채로 저장한다(재설계 스펙 5.4).
  - 미리보기는 서버 경로 API에 `departAt`을 주어 시간표 열차를 받는다. 서버가 `departAt + 탑승 전 시간` 이후 열차를 주므로, 루틴의 걷는 시간에 맞게 `departAt`을 당겨 보낸다. 앱이 방향(상행·하행)을 몰라도 된다.
  - 경로 상세에서 편집 화면으로 경로를 넘길 때는 내비게이션 인자 대신 앱 컨테이너에 잠시 둔다(경로 JSON이 길다).
- 막혔던 점과 해결:
  - 알람으로 깨어난 수신기는 짧게만 살아 있다. `goAsync`로 세션 시작까지 기다린다.
- 예상 면접 질문과 내 답:
  - Q. 루틴 시각에 폰이 꺼져 있었다면? A. 켜질 때 `BOOT_COMPLETED`로 다음 실행부터 다시 예약한다. 지난 실행은 되살리지 않는다.
