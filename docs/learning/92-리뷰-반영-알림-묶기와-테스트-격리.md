# 92. 코드 리뷰 반영: 알림 묶기, 두 번 누름, 테스트 격리

- 무엇을 만들었나: 2026-11-17 코드 리뷰에서 나온 8건을 고쳤다.
  - 앱: 역을 빠르게 두 번 눌러 `returnPick`이 두 번 불리면, 두 번째 호출이 결과를 받을 화면(경로 편집)까지 닫았다. 맨 위가 검색 화면이 아니면 아무것도 하지 않게 했다.
  - 서버: 하루 한도 설정에 음수를 넣으면 "제한 없음"이 됐다. 설정 단계에서 음수를 받지 않는다(`NonNegativeInt`). 0만 제한 없음이다.
  - 밤 작업: 확정 줄마다 Discord로 따로 보내던 것을 2,000자 이하 메시지로 묶는다(`chunk_lines`, `send_lines`).
  - 같은 모양이던 두 `main`의 "알림 함수 만들기 → 예외 잡기 → 실패 알림"을 `run_with_alert` 하나로 모았다.
  - httpx 로그를 끄는 코드가 네 곳(서버, 수집기, 공식 시간표, 알림)에 흩어져 있었다. `app.core.logging.quiet_http_loggers()` 하나로 모으고, 알림 함수를 만들 때 생기던 부수 효과를 없앴다.
  - 테스트: 환경에 웹훅이 있으면 테스트가 진짜 Discord로 알림을 보낼 수 있었다. 모든 테스트에서 그 변수를 지우는 autouse 픽스처를 두었다. 로거 수준을 바꾸는 테스트는 끝나면 원래대로 돌린다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 429를 막는 방법으로 "보낼 때마다 잠깐 쉬기"도 있었다. 하지만 묶어 보내면 요청 수 자체가 줄어 연결 비용도 함께 준다. 한 밤에 2,000자를 넘는 확정은 드물어 대개 메시지 한 개로 끝난다.
  - 음수 한도를 0으로 바꿔 받는 대신 서버가 아예 뜨지 않게 했다. 오타를 조용히 "제한 없음"으로 바꾸는 것보다, 배포 직후 실패해서 바로 보이는 쪽이 안전하다.
- 막혔던 점과 해결:
  - bash heredoc 안의 파이썬 문자열에 `"\\n"`을 쓰면, 파일에 진짜 줄바꿈이 들어가 문법 오류가 났다. 그 부분은 편집 도구로 직접 고쳤다.
  - 두 번 누름은 Robolectric에서 `returnPick`을 연달아 두 번 부르는 테스트로 재현했다. 고치기 전에는 실패하는 것을 확인했다.
- 예상 면접 질문과 내 답:
  - Q. 테스트가 외부 서비스를 부르지 않게 하는 일반적인 방법은?
  - A. 비밀값과 주소는 환경에서 읽되, 테스트 전체에 걸리는 픽스처로 그 환경을 비운다. 외부 요청은 respx 같은 흉내 도구로 막는다. 이렇게 하면 개발자 PC나 서버의 환경이 테스트 결과나 실제 채널에 새어 들지 않는다.
