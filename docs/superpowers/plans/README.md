## 실행 방법

- 계획마다 시작하기 직전에 다시 읽고, 앞 계획의 결과로 바뀐 값이 없는지 본다. 특히 P1이 남기는 `docs/analysis/api-verification.md`(실제 필드 이름, 응답 코드, 카카오 경로 필드 대응표, 역 이름 예외)가 P2의 표와 테스트 값을 정한다. P1 Task 8이 이 반영을 맡는다.
- 작업 하나는 "실패하는 테스트 → 구현 → 통과 → 커밋" 순서다(스펙 12절). "(직접)"이 붙은 단계는 계정·키·실기기가 필요해 사람이 한다.
- 각 계획 머리말의 브랜치 묶음대로 PR을 만들고, 본인이 읽은 뒤 머지한다.
- 점검일 11/15(P3 끝)와 11/20(P4 중간)에 끝나지 않은 기능은 스펙 3.4절의 최소 버전으로 마무리한다. 각 작업에 해당 최소 버전을 적어 두었다.

## 계획을 쓰며 스펙에 반영한 것

스펙 [부록 B](../specs/2026-11-02-jigeumchulbal-mvp-design.md#부록-b-변경-이력)에 전부 적었다. 요약:

- 실제 저장소(`klanary/subway_easy`)와 패키지명(`io.github.klanary.jigeumchulbal`)
- 이름은 같지만 멀리 떨어진 역(5호선 양평과 경의중앙선 양평)을 한 역으로 묶으면 좌표 평균이 두 역 사이의 엉뚱한 곳이 되므로 따로 나눈다
- 이미 역을 떠난 열차("OO 출발")는 도착 목록에서 뺀다. 서울시 API의 "데이터 없음"은 오류가 아니라 빈 목록이다
- `/health`는 요청 제한에서 뺀다(Render 헬스 체크가 막혀 재시작되는 것을 막음). httpx 기본 로그가 서울시 키가 든 URL을 남기지 않게 한다
- 출발 알림 뒤 "놓쳤다"고 판단하는 기준을 "출발 시각 + 60초"에서 "그 열차 도착 예정 + 60초"로 바꿨다. 기존 기준은 알림대로 출발해 역으로 걷는 사람을 놓친 것으로 처리했다
- 통합 검색의 역 결과에 [실시간] 버튼을 둬, 즐겨찾지 않은 역의 실시간 도착으로 갈 길을 만들었다(T3 측정에 필요)
- P6에서 정한 것은 위치 결합 스펙 [13절](../specs/2026-11-05-train-position-fusion-design.md#13-구현-계획에서-정한-것-p6-2026-11-05)에 적었다(근처 열차 API의 `stopsFromStation`, 노선 표의 `loopEnds`, 상태 머신의 `BoardedDetected` 등)
