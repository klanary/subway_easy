# 12. 앱의 서버 통신 계층과 오류 분류

- 무엇을 만들었나: 서버 응답 형식(스펙 6.2)을 그대로 옮긴 DTO, Retrofit `ApiService`, 서버 호출을 `ApiResult`(성공·오류)로 바꾸는 `safeApiCall`, 역·장소·경로·서버 저장소(인터페이스 + `Default…` 구현), 의존 객체를 손으로 연결하는 `AppContainer`.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 앱은 서버 형식만 안다. 서울시·카카오 형식은 서버가 바꿔 주므로, DTO를 화면 모델로 그대로 쓴다. 변환 계층을 하나 더 두는 대안보다 코드가 적고, 형식이 바뀌면 서버와 DTO만 고치면 된다.
  - 오류를 네 가지로 나눴다: 오프라인(기기 연결 없음), 네트워크(연결은 있는데 서버에 못 닿음), 서버 오류(스펙 6.3의 `code`·`message`), 그 밖. 화면은 이 구분으로 "오프라인"과 "다시 시도"를 다르게 보여준다(스펙 4.5).
  - `CancellationException`은 잡지 않고 다시 던진다. 코루틴 취소는 "화면을 떠났다"는 신호인데, 오류로 잡으면 떠난 화면에 오류가 뜨거나 자동 갱신 루프가 멈추지 않는다.
  - 읽기 시간 제한을 65초로 길게 두었다. Render 무료 서버가 잠들었다 깨어나는 데 1분 가까이 걸려, 짧게 두면 첫 요청이 늘 실패한다.
  - 저장소를 인터페이스로 둔다. ViewModel 테스트가 실제 네트워크 없이 가짜 저장소로 돈다. 의존성 주입 라이브러리(Hilt) 대신 `AppContainer`로 손으로 연결해, 무엇이 어디서 만들어지는지 코드에 그대로 보인다(스펙 5.3).
- 막혔던 점과 해결:
  - "현재 위치"를 경로 요청의 출발 이름으로 보내면 카카오 경로에 "현재 위치"라는 장소 이름이 넘어간다. 현재 위치일 때는 이름 파라미터를 보내지 않게 하고 테스트로 고정했다.
- 예상 면접 질문과 내 답:
  - Q. 독일어처럼 소수점이 쉼표인 지역 설정에서도 좌표가 맞게 가나요? A. `Double.toString`은 지역 설정과 관계없이 "."을 쓴다. `String.format`을 쓰면 지역 설정을 따라 깨질 수 있어서, 독일 지역 설정에서 쿼리를 만드는 테스트를 두었다.
  - Q. 서버가 HTML 오류 페이지를 돌려주면? A. 오류 본문이 스펙 형식이 아니면 `HTTP_상태코드`와 일반 문구("서버에 문제가 생겼어요")로 바꾼다.
