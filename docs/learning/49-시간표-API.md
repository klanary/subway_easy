# 49. 서울시 시간표 해석과 시간표 API

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 서울시 역별 시간표(`SearchSTNTimeTableByIDService`)를 부르는 클라이언트, 순수 함수 `week_tag`·`service_days`·`parse_hms`·`departures`, `GET /v1/stations/{id}/timetable?line=&direction=&from=&count=`.
- 왜 이렇게 했나:
  - 실시간이 없는 역과 "1시간 뒤" 열차는 시간표로만 알 수 있다(재설계 D11).
  - 요일은 공휴일·일요일 3, 토요일 2, 그 밖 1. 공휴일은 `holidays`의 한국 달력(대체공휴일·선거일 포함)으로 외부 호출 없이 판단한다.
  - 시간표는 하루 안에 바뀌지 않으므로 역 코드·요일·방향별로 하루 캐시한다. 같은 평일이면 다른 날에도 같은 캐시를 쓴다.
  - 시간 계산을 순수 함수로 떼어 두어 실제 응답 샘플만으로 테스트한다.
- 막혔던 점과 해결:
  - 막차는 "24:34:10"처럼 24시를 넘겨 적힌다. 그 운행일 0시에 시간을 더해 다음 날로 넘긴다. 새벽 0~4시에는 전날 시간표도 함께 본다.
  - 종착역에서는 출발 시각이 "00:00:00"이다(방화역 확인). 그 역에서 끝나는 열차는 뺀다.
  - 일반 OpenAPI 주소(`:8088/{키}/`)도 로그에서 키를 가리도록 마스킹 규칙을 넓혔다.
  - 데이터 없음(`INFO-200`)은 서비스 이름 없이 본문 바로 아래 `RESULT`로 온다.
- 예상 면접 질문과 내 답:
  - Q. 시간표 API 한도를 넘으면? A. 하루 캐시라 역·요일·방향 조합 수만큼만 부른다. 한도의 80%를 넘으면 다른 API처럼 캐시 유효 시간이 늘고, 넘으면 503으로 알린다.
