# 95. 릴리스에서 결과물 받기

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: `server/app/services/measured_store.py`. GitHub 릴리스의 `manifest.json`을 보고 `built_at`이 바뀌었을 때만 두 결과물을 받는다. sha256·gzip·형식이 맞을 때만 바꾸고, 틀리거나 실패하면 지난 것을 쓴다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 요청이 받기를 기다리지 않는다. `current()`가 6시간마다 백그라운드 작업 하나만 띄운다. 무료 서버는 잠들므로 따로 도는 스케줄러보다 "요청이 올 때 확인"이 맞다.
  - manifest를 마지막에 올리고 sha256으로 확인해서, 올리는 도중의 파일을 쓰지 않는다.
  - `as_of`가 14일보다 오래되면 쓰지 않는다. VM이 멈췄는데 옛 시각을 계속 보이는 것을 막는다.
- 막혔던 점과 해결:
  - 테스트에서 결과물을 넣을 길이 필요해 `replace()`를 공개했다. 받기도 같은 함수를 써서 경로가 하나다.
- 예상 면접 질문과 내 답:
  - Q. 받는 도중 서버가 재시작되면?
  - A. 메모리에만 두므로 처음부터 다시 받는다. 그동안은 실측 없이(예전처럼) 응답한다.
