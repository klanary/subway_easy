# 36. 탑승 중 추적 상태와 탄 열차 정하기

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 통학 세션의 탑승 상태(`Riding`)에 추적 정보(`Tracking`: 따라가는 단계, 호선, 내릴 역, 열차 번호, 출처, 실패 수, 끊김)를 더했다. 탄 열차를 정하는 사건 두 개(`BoardedDetected`, `TrainIdentified`)와 알림 두 개("OO행 열차에 탄 것으로 보여요", "어느 열차에 탔나요?")를 더하고, 대기 서비스 효과를 세션 서비스 효과로 이름을 바꿨다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 탄 열차는 "위치로 알아낸 열차 → 승차 전 알림이 계획한 열차 → 직접 고르기" 순서로 정한다(위치 결합 스펙 7.1). 위치는 실제로 움직인 증거라 계획보다 앞선다.
  - 하차 지점(`AlightPoint`)에 호선·탄 역·내릴 역·다음 정거장을 함께 저장했다. 저장된 세션에는 경로 좌표를 빼고 넣으므로, 추적과 감지에 필요한 값은 지점에 남겨 둬야 앱을 다시 열어도 이어서 추적할 수 있다.
  - 추적할 지하철 단계가 있으면 탑승해도 서비스를 멈추지 않는다. 대기 서비스를 그대로 "세션 서비스"로 넓혀 탑승 중 추적에도 쓴다(7.3). 추적할 단계가 없으면 예전처럼 멈추고 알람만 남긴다.
  - 직접 고르기(MANUAL)로 열차를 정하면 서비스를 다시 켜는 효과를 낸다. 화면에서 고르므로 안드로이드의 "백그라운드에서 포그라운드 서비스 시작 금지"에 걸리지 않는다. 자동 감지(AUTO)는 이미 도는 서비스 안에서 일어나므로 켜지 않는다.
  - 새 칸에는 모두 기본값을 줬다. 업데이트 전에 저장된 탑승 세션 JSON에는 이 칸이 없는데, 기본값이 없으면 복원에 실패해 남은 알람이 사라진다.
- 막혔던 점과 해결:
  - 재부팅 복원에서는 포그라운드 서비스를 켤 수 없다. 그래서 복원 계획(`planRestore`)이 재부팅일 때만 서비스 시작을 빼고, 알람은 그대로 되살린다.
- 예상 면접 질문과 내 답:
  - Q. 예전 버전 앱이 저장한 세션을 새 버전이 읽을 수 있나? A. 새 칸이 모두 기본값을 가지고 JSON 설정이 모르는 키를 무시하므로 읽힌다. 테스트(`oldSavedRidingStateStillLoads`)로 확인했다.
  - Q. 사용자가 다른 단계의 열차를 늦게 고르면? A. `TrainIdentified`에 단계 번호를 실어 보내고, 지금 추적 중인 단계와 다르면 무시한다.
