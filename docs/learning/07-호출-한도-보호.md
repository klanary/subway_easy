# 07. 외부 API 일일 호출 한도 보호

- 무엇을 만들었나: 외부 API별 일일 호출 수·오류 수를 세고, 한도의 80%부터 캐시 유효 시간을 3배로 늘리며, 한도에 닿거나 외부 API가 한도 초과로 응답하면 그날 호출을 멈추는 `QuotaGuard`. 한국 시간 자정에 초기화된다. 앱 조립 때 서울 실시간·카카오 경로·키워드·좌표→주소 4개를 만든다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 서울시 실시간 도착 API는 하루 1,000회다. 한도를 넘기면 그날 앱의 핵심 기능이 멈추므로, 넘기기 전에 캐시를 길게 써서 호출을 줄이고(80% 구간), 닿으면 호출을 멈추고 만료 캐시로 버틴다.
  - 자정 초기화는 타이머 없이 "접근할 때 날짜가 바뀌었는지 확인"으로 했다. 백그라운드 작업이 필요 없고, 시계를 주입해 테스트에서 23:59:59 → 00:00:00을 바로 확인할 수 있다.
  - 카운터가 메모리에 있어 서버가 재시작되면 0이 된다. 외부 API의 한도 초과 응답을 받으면 `mark_exhausted()`로 그날 호출을 멈춰 이 한계를 보완한다(스펙 6.4).
- 막혔던 점과 해결:
  - 날짜 비교는 UTC가 아니라 한국 시간 날짜로 해야 한다. 한국 시간 00:00은 UTC로 전날 15:00이라, UTC 날짜로 비교하면 오전 9시에 초기화된다.
- 예상 면접 질문과 내 답:
  - Q. 서버를 여러 대로 늘리면? A. 카운터가 서버마다 따로 있어 한도를 나눠 쓰지 못한다. 그때는 Redis 같은 공유 저장소의 원자적 증가(INCR)와 만료 시간으로 옮긴다. 지금은 한 대라 메모리로 충분하다.
  - Q. 80%와 3배는 어떻게 정했나요? A. 남은 20%로 하루를 버티도록 캐시를 길게 쓰는 단순한 기준이다. 부하 테스트(S3) 결과를 보고 조정할 수 있게 상수로 두었다.
