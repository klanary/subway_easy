# 50. 실시간이 없으면 시간표로 대신하기

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 도착 응답의 그룹마다 `source`(`realtime`, `timetable`, `none`)를 붙였다. 실시간 그룹이 없는 방향은 시간표 2대로 채우고, 비서울 노선은 빈 `none` 그룹을 넣는다.
- 왜 이렇게 했나:
  - 실시간 API가 다루지 않는 역(진접, 별내별가람 등)도 서울 노선이면 시간표로 다음 열차를 보일 수 있다(재설계 D4).
  - 호선 단위가 아니라 방향 단위로 채운다. 상행만 실시간이 오고 하행이 비는 경우가 있기 때문이다.
  - 앱은 `source`만 보고 "시간표 기준", "실시간 정보를 제공하지 않는 노선이에요"를 고른다.
- 막혔던 점과 해결:
  - 시간표 호출이 실패해도 실시간 결과는 그대로 보여야 한다. 시간표 오류는 로그만 남기고 그 방향을 뺀다.
  - 종착역(진접)은 그 역에서 끝나는 방향의 열차가 모두 빠져 한 방향만 남는다. 맞는 동작이다.
  - 기존 도착 테스트가 모의하지 않은 시간표 호출로 실패했다. 테스트 파일에 "데이터 없음" 기본 모의를 이름 붙여 두고, 필요한 테스트만 같은 이름으로 바꿔 끼우게 했다.
- 예상 면접 질문과 내 답:
  - Q. 시간표 그룹에는 왜 방면(towards)이 없나? A. 시간표에는 행선지만 있고 다음 역 정보가 없다. 대신 방향(상행·하행)과 행선지를 보인다.
