# 108. 경로 상세의 열차 고르기 화면과 더 늦은 열차 불러오기

> Claude Code가 쓴 초안이다. 본인이 직접 고쳐 쓴다(스펙 12절).

- 무엇을 만들었나: 경로 상세의 지하철 단계마다 `[◀ 이전] 08:05 출발 → 08:09 도착 · 5301 [다음 ▶]` 줄을 두었다. 급행과 일반이 함께 다니는 구간에는 전체/급행/일반 칩, 고정한 구간에는 `📌 고정됨 [고정 풀기]`, 어긋나면 빨간 경고가 나온다. 맨 위 총 소요와 [지금 출발 알림]·루틴 만들기는 고른 열차로 바꾼 경로(`pickedRoute`)를 쓴다. 후보 끝에서 [다음]을 누르면 그 시각 + 1분으로 경로를 다시 받아, 지하철 구간 열(노선·탄 역·내릴 역)이 같은 경로의 후보를 구간마다 합친다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 고른 상태는 검색 결과를 함께 쓰는 `RouteFlowViewModel`에 두었다. 경로를 다시 고르거나 다시 찾으면 비운다.
  - "더 늦은 열차"는 검색 조건(출발 시각)을 바꾸지 않고 후보만 합친다. 결과 목록이 갑자기 바뀌면 사용자가 헷갈린다.
  - 같은 경로를 id가 아니라 구간 열로 찾는다. id도 같은 규칙으로 만들지만, 구간 열로 비교하는 편이 뜻이 분명하다.
- 막혔던 점과 해결:
  - 단계 목록이 다리(경유)마다 나뉘어 있어, 지하철 단계마다 몇 번째 구간인지를 먼저 계산해 고르기 상태와 맞췄다.
- 예상 면접 질문과 내 답:
  - Q. 페이지네이션처럼 데이터를 더 불러올 때 무엇을 조심했나?
  - A. 중복(번호+출발 시각)을 없애고 정렬을 다시 하고, 불러오는 동안 버튼을 꺼서 두 번 부르지 않게 했다. 실패하면 상태를 그대로 둔다.
