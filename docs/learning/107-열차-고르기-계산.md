# 107. 열차 고르기 계산(고정·자동 맞춤·경고)

- 무엇을 만들었나: `ui/routedetail/TrainPicker.kt`에 순수 함수 `pickTrains`·`move`·`setFilter`·`unpin`·`withPicks`를 두었다. 구간마다 고정한 열차는 그대로 쓰고, 고정하지 않은 구간은 앞 열차가 내린 시각 이후(같은 초 포함) 떠나는 첫 후보로 맞춘다. 고정한 열차가 앞 열차 도착보다 먼저 떠나면 "앞 열차가 08:20에 도착해요. 이 열차는 08:10에 떠나요"라고 경고한다.
- 왜 이렇게 했나 (검토한 대안과 고른 이유):
  - 상태를 "구간마다 고정한 열차와 급행 필터"만으로 두고, 화면에 보일 값은 매번 처음부터 다시 계산한다. 앞 구간을 바꾸면 뒤 구간이 저절로 다시 맞춰져서 상태끼리 어긋날 일이 없다.
  - 안드로이드에 의존하지 않는 함수라 JVM 단위 테스트로 열 가지 경우를 빠르게 확인했다.
  - 필터를 바꿨는데 고정한 열차가 새 필터에 맞지 않으면 고정을 푼다. 보이지 않는 열차가 고정된 채 남지 않게 하려는 것이다.
- 막혔던 점과 해결:
  - 후보가 없는 옛 서버 응답도 깨지지 않게, 후보가 비면 경로가 정한 열차 하나를 후보로 본다.
- 예상 면접 질문과 내 답:
  - Q. 파생 상태를 저장하지 않고 계산하는 이유는?
  - A. 저장한 값이 하나라도 갱신을 놓치면 화면이 틀린다. 입력(고정·필터)만 저장하고 출력은 함수로 만들면 늘 일관된다.
